# Pilot-study ledger

Generated by `tools/pilot_metrics.py` from the main checkout (read-only), its worktrees, CLI logs, receipts, shared ledger, and `predictions.json`. No network or card access.

Rerun from the S8-06 worktree: `python tools/pilot_metrics.py`. Optional: `--repo PATH --ledger PATH --predictions PATH --output PATH`.

Hours are first-to-last timestamped event per session, summed across sessions; overlapping sessions are not de-overlapped. Unknown means absent evidence, never zero effort. Timestamp-free CLI logs still count as sessions; filesystem timestamps are not duration evidence. Tokens are retained by category in metrics.json; cached input is part of input, not added again.

Twin counts include all commands, not just simulations. Exact JSON copies across worktrees count once; original invocation cwd/artifact path determines ownership before the copy path. Host seconds use the overall Python execution field, not a sum of nested timing fields. Receipts count once per job ID; receipt ownership follows its ticket path. Ledger allocation windows are separate from application jobs and do not add whole-window minutes. Receipt minutes include staging and are not application wall times. Missing window IDs stay unknown.

Model and variant flags use Engineer-report evidence and explicit model prediction rows; ticket instructions alone do not establish use. Outcome quotes the first report paragraph, truncated at 180 characters. No means no positive recorded evidence.

## Scoring

Ratio = measured / predicted, only for the same numeric unit and scope. Direction compares the sign of change against a common baseline, or explicit winner names. Range ratios show the endpoint interval without inventing a midpoint. `decided`/`missed` require a comparable card direction; `unsupported` records a refusal; `not-attempted` includes predictions whose card comparison has not been attempted or cannot be scored. Functional host checks and whole-run timings cannot validate force-only cycle predictions.
