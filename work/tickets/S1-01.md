# S1-01 Sources, x86 reference build, sample workunits, compare tool

Sprint 1. Depth: standard. Network: yes (fetch only).

## Why
Every later step compares the card against an x86 build of the same pinned sources on the same inputs.

## Do
1. `scripts/fetch.sh`: clone https://github.com/Milkyway-at-home/milkywayathome_client into `third_party/` at a pinned
   commit (the newest release tag whose N-body version is what MilkyWay@home distributes now; say how you decided),
   plus only the submodules or bundled libraries a standalone N-body build needs. Idempotent. Record repo, tag, commit
   and licence in `SOURCES.md`. Do not fetch BOINC here unless the standalone build cannot avoid it.
2. A hand-written build (`mk/` Makefile + checked-in generated config headers under `config/`, no CMake) for
   `milkyway_nbody` **standalone**: BOINC off, OpenCL off, OpenMP on, double precision, the default (non-crlibm) math
   unless upstream requires otherwise (say which and why). `make x86` builds with Cygwin g++ into `build/x86/`.
   Keep the source list and flags in one place so S1-02 adds a `card` target with the same sources.
3. `workunits/`: two cases from upstream's own N-body tests or sample files: `small` (under 30 s on one x86 thread)
   and `medium` (2-10 min on one x86 thread), each with its Lua parameter file, input histogram and exact command line
   in `workunits/README.md`. Prefer cases that print a likelihood.
4. `scripts/compare.py A B`: parse two runs' outputs (likelihood and output histogram, whatever the app prints/writes)
   and report absolute/relative differences and PASS/FAIL against a tolerance. Take the tolerance from MilkyWay's own
   validator or test-suite rule in the upstream source (cite file:line); if none exists, propose one and flag it.
5. Run x86 on both cases at 1 and 4 OpenMP threads, store outputs under `runs/x86/` (gitignored) and record in the
   report whether 1 and 4 threads are bit-identical.

## Acceptance
- `bash scripts/fetch.sh && make -C mk x86` works from a fresh clone of this repo.
- `python -m unittest discover tests` passes, including a compare.py test that fails on a doctored output.
- Both workunits run on x86; the report gives run times, likelihoods and the 1-vs-4-thread result.


## Engineer report

Implemented in the S1-01 worktree; no commit, index, branch or lead-facing message was made.

- Pinned `nbody_1.97`, commit `d78c48fc9905ee309e28ae4b76ad2f6fda901ef8`.
  On 2026-11-15 the official applications page distributed ordinary N-body 1.96
  and N-body with Orbit Fitting 1.97. Selected the newest matching release,
  the Orbit Fitting version; source version definitions agree. Provenance,
  licences, bundled dependencies and selection evidence are in `SOURCES.md`.
- `scripts/fetch.sh` clones only that upstream repository, shallow and without
  submodules, verifies HEAD and applies two idempotent Cygwin patches. OpenSSL
  is selected per Git invocation because Windows Schannel failed in this session.
  No BOINC or other sources were downloaded. A second fetch leaves patches applied.
- Added handwritten `mk/Makefile`, explicit shared source/flag manifest
  `mk/sources.mk`, and expanded upstream configuration headers under `config/`.
  Cygwin gcc compiles C99; Cygwin g++ compiles the C++ helper and links.
  BOINC/OpenCL/crlibm/curses/graphics are off; OpenMP and double precision are on.
  Non-crlibm system math is used except upstream 1.97's mandatory bundled
  CORE-MATH erf/cbrt/gamma functions. IEEE flags are retained, without fast-math.
  One patch avoids popt redeclaring Cygwin's glob_pattern_p; the other selects
  CORE-MATH's existing round-to-even fallback because Cygwin lacks the emitted
  roundeven libm symbol. No numerical algorithm was replaced.
- Both workunits are LF-normalized copies of upstream `orphan_models/model_1.lua`
  and `orphan_model_histogram_3`, parameterized at 64 / 1024 bodies with upstream
  test seed 670828913. Exact command lines and provenance: `workunits/README.md`.
  An initial copied CRLF histogram exposed the upstream reader's exact LF tag
  matching; checked-in workunits and future fetched sources now retain LF.
- `scripts/compare.py A B` reads run directories, compares likelihood and every
  histogram value/error/metadata field, reports absolute and relative errors,
  and returns PASS/FAIL. Likelihood acceptance is the upstream strict absolute
  difference `< 1e-10` (`nbody/tests/RunTestUnits.lua:137-139`). Applying that
  bound to histogram numeric fields is explicitly a PROPOSED extension, not an
  upstream validator rule. Bin identities and shapes must match exactly;
  missing/malformed/non-finite data fail. Relative errors are diagnostics.
