# S1-01 Sources, x86 reference build, sample workunits, compare tool

Sprint 1. Depth: standard. Network: yes (fetch only).

## Why
Every later step compares the card against an x86 build of the same pinned sources on the same inputs.

## Do
1. `scripts/fetch.sh`: clone https://github.com/Milkyway-at-home/milkywayathome_client into `third_party/` at a pinned
   commit (the newest release tag whose N-body version is what MilkyWay@home distributes now; say how you decided),
   plus only the submodules or bundled libraries a standalone N-body build needs. Idempotent. Record repo, tag, commit
   and licence in `SOURCES.md`. Do not fetch BOINC here unless the standalone build cannot avoid it.
2. A hand-written build (`mk/` Makefile + checked-in generated config headers under `config/`, no CMake) for
   `milkyway_nbody` **standalone**: BOINC off, OpenCL off, OpenMP on, double precision, the default (non-crlibm) math
   unless upstream requires otherwise (say which and why). `make x86` builds with Cygwin g++ into `build/x86/`.
   Keep the source list and flags in one place so S1-02 adds a `card` target with the same sources.
3. `workunits/`: two cases from upstream's own N-body tests or sample files: `small` (under 30 s on one x86 thread)
   and `medium` (2-10 min on one x86 thread), each with its Lua parameter file, input histogram and exact command line
   in `workunits/README.md`. Prefer cases that print a likelihood.
4. `scripts/compare.py A B`: parse two runs' outputs (likelihood and output histogram, whatever the app prints/writes)
   and report absolute/relative differences and PASS/FAIL against a tolerance. Take the tolerance from MilkyWay's own
   validator or test-suite rule in the upstream source (cite file:line); if none exists, propose one and flag it.
5. Run x86 on both cases at 1 and 4 OpenMP threads, store outputs under `runs/x86/` (gitignored) and record in the
   report whether 1 and 4 threads are bit-identical.

## Acceptance
- `bash scripts/fetch.sh && make -C mk x86` works from a fresh clone of this repo.
- `python -m unittest discover tests` passes, including a compare.py test that fails on a doctored output.
- Both workunits run on x86; the report gives run times, likelihoods and the 1-vs-4-thread result.
