# S10-03 Serial parts of body generation on the card (bodies byte-identical)

Sprint 10. Depth: deep. No card access. Laptop load light; at most one full 117676 generation (final build only).

## Why
Core-small on the card (S9-05 build, real 117676 Lua and arguments): 47.6 s, almost all in body generation (setup
46.9 s). The same derivative reuse gave 1.65x on the laptop but only 1.32x on the card, so the card spends a larger
share outside the parallel quadrature: `vel_mag` / `max_finder` iterations, `dist_fun`'s root finding and search
range, `r_mag`, the RNG, the per-body serial loop. One card thread runs this x87 code ~12x slower than a laptop core.

## Do
1. Generator sub-phase timers (option `GEN_PROFILE`, off by default): time inside the parallel node evaluation vs
   serial per-integral work vs per-body serial work (max_finder, rejection loop, r_mag, RNG, get_components), plus
   counts (integrals per body, attempts per body). Stage a card job for core-small with the release options
   (S10-01, or S9-05's if not ready) and give a prediction of the split.
2. Exact candidates for the biggest serial term, each behind its own option, bodies byte-identical: e.g. parallelize
   the serial parts inside one integral (search range, root finding via speculative bracketing evaluated in parallel
   with the original decision order), or speculative pipelining across bodies (evaluate the next body's `max_finder`
   for the radius the RNG would give if the current body accepts on its next attempt; discard on mismatch), keeping
   the dSFMT order and every decision identical. Pick by the timer data; justify.
3. Proof: core-small bodies byte-identical and likelihood bit-identical; for the final selection, the full 117676
   generation byte-identical (one run).
4. Card binaries, knc_lint, window script (core-small), predictions recorded before the card run.

## Accept
- Timer plan and prediction, selected change, proof output, binaries, window script and the Effort line.
