## Engineer report

Implemented `scripts/e2e_card.sh` with a standard-library Python driver and an
`e2e-card` scenario in the existing S2-01/S2-04 Windows fake client. This scenario
uses real upstream BOINC IPC and launches the packaged wrapper without a fake
card. The launcher builds nothing. It prepares resolved BOINC slot names, the
unchanged small/medium workunit and the requested real Windows OpenSSH config.
The default is medium with 4 threads; valid thread counts are 1..240.

After receiving a live snapshot, the client runs 60 seconds, launches packaged
graphics halfway through that phase and captures its live framebuffer, suspends,
lets the driver verify card state T in one `ps -o stat=` SSH call, holds 30
seconds, resumes, verifies a checkpoint exists, quits through the wrapper's
acknowledged checkpoint transfer, and restarts from those saved slot bytes.
It requires successful completion and the upstream checkpoint-restore diagnostic.
Both launches' application PIDs, remote directories and processes retaining the
lease working directories (including deleted directories) are checked gone.
Failures request abort through IPC and retain evidence; unverified cleanup is
never reported as successful.

Live evidence goes under `runs/e2e/<UTC timestamp>/`: summary JSON, detailed
phase wall times, verification transport log, fake-client log, wrapper log,
suspend ps evidence, complete slot/results/restart checkpoint, live BMP/PNG,
fresh single-thread x86 reference and the strict `< 1e-10` likelihood comparison.
The PNG is also written to `docs/img/live-card.png` during suspension.
The dry run prints all transport operation templates for both launches, including
concrete runtime names from the package when present. Runtime lease/PID values
and polling/retry counts are symbolic. It starts no processes on the card and
does not create a slot/run or launch the client, graphics or reference.

The ledger guard replays queued/start/close events by job ID and refuses open
foreign or unknown-project reservations, including reopened queues. Missing or
malformed ledgers fail closed. `--in-granted-turn` bypasses this check only when
the lead supplies it after receiving the turn. Dry runs need no ledger turn.
No ledger writes occur. Operational details are in `docs/e2e-card.md`.
