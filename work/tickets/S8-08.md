# S8-08 Force walk on the card: model and a cache-friendly layout (results bit-identical)

Sprint 8. Depth: deep, fast turnaround. No card access. Deadline: model plus card binaries within 75 minutes.
Start from main. Use the knc-optimize method and the knc-twin skill (one core with 4 contexts, and the 8-tile ring
mode `simulate --scale ring` for memory/ring effects; multicore is an unvalidated estimate).

## Why
Card, large case: force walk 13.0 s (scalar) and 13.1 s (S6-03 vector walk, `VECTOR_GRAVITY=1`) at 240 threads;
laptop 12 threads 20.4-25.0 s. The twin predicted the vector walk keeps lanes 79-94% busy, yet the card shows ~2%
gain, so the walk is probably bound by memory latency (tree nodes and bodies scattered in memory, pointer chasing
through `Next`/`More`), not by arithmetic. Work per body: 13.0 s x 240 threads / (20,000 x 111) = ~1.4 ms
thread-time per body.

## Do
1. Count per step (x86 debug counters, not in the card timing build): body-cell and body-body interactions,
   nodes visited, distinct cache lines touched per body walk. Write the Model table in
   `docs/research/s8-force-model.md`: FP64 ops (~20-25 per interaction incl. sqrt/div), bytes, T_lb for
   compute (1.2 TFLOPS FP64 peak, and x87 scalar rate from the knc-optimize machine file) and for latency
   (lines x latency / concurrency), vs measured 13.0 s. Name the dominant term.
2. knc-twin: the inner walk loop from the card binary (scalar and vector builds) on one core, 4 contexts, with the
   real tree as memory input if the twin accepts it; and the 8-tile ring run if it does. Report status and
   result_class as returned; unsupported is an answer.
3. Layout variant `NBODY_WALK_LAYOUT` (off by default): after `threadTree`, copy the cells (and bodies) into
   contiguous arrays in walk order (`Next`/`More` order) and walk those, with software prefetch of the next nodes
   (`_mm_prefetch` / IMCI `vprefetch0/1` by hand where the compiler does not). Same interactions in the same order:
   results bit-identical. Card binaries `build/s8/walk-layout{,-vec}/milkyway_nbody.mic` with timers, chunk 4,
   parallel quad, static integrator. If the compiler could do the prefetch or layout part, say so with evidence
   (compiler-first rule in AGENTS.md).
4. x86: `scripts/compare.py` bit-identical (small, medium, large at 1 and 12 threads) and PHASE lines; knc_lint;
   card_run commands for the large case and core-small (`workunits/core-small`, real 117676 args as in
   `.work/S8-03/build/s8/card-quad/card-command.sh`).
