# S5-01 knc-twin ranking of compile-flag variants for the gravity kernel

Sprint 5 (speed on the card, twin first; the card is busy). Depth: medium. knc-twin at ~/.claude/skills/knc-twin
(0.4.x; read `references/handoff-prompt.md`). No card access.

## Why
The card run (docs/sprints/sprint-1.md) is bit-identical to x86 but slow on small/medium. Before any card A/B, rank
cheap compiler-side options for `nbGravity` (the per-body tree walk; `x87_serial` and `resource` bind in S1-06).

## Rules
- Every variant must keep the project's numerics: no `-ffast-math` or its parts, keep `-ffp-contract=off`,
  `-fno-math-errno` and crlibm. A variant counts only if its twin `functional` output equals the x86 bits.
- Known twin defect: x87 double rounding (gcc-knc S14-37, `twin/x87-rounding-repro.json`) makes some bodies differ
  by 1 ULP. Use inputs that pass on the baseline: the S1-05 small capture and large-case bodies 0, 128, 256, 384
  (S1-06/S1-07 tooling). Say which inputs, and exclude none after seeing results.
- Same profile (`card-7120-measured`), scenario and unit of work for all variants; rank with `batch`, not by hand.

## Do
1. Variants (at most 6, rebuild only `nbody_grav.c` per variant; link the rest unchanged): V0 the current flags;
   `-O3`; `-mphinix -ffp-contract=off`; `-O2 -funroll-loops`; plus up to two of your choice from
   `C:/Users/xuzhi/Documents/gcc_knc/docs/gcc-knc-flags.md`, each with one line on why. If a variant changes
   numerics, record it and drop it.
2. For each: from_binary extraction (S14-20 is on main: no region cut needed now; say if any variant still needs
   one), `functional` on the inputs above, `simulate`, then `batch` over all passing variants.
3. Run `schedule` on V0's hot loop (beam or list) to see how much a reorder could gain under the model; report it
   as the twin reports it.
4. `prepare-native` requests (no card) for the top variant vs V0, so the lead can A/B on the card later.
5. Write `docs/twin-flags.md`: table of variant, functional status, predicted cycles per call, change vs V0,
   result_class, limiting constraints; the winner only if it beats V0 by more than the validated error, otherwise
   say "too close for the twin".

Findings and remaining blockers:

- V1/V2 inline nbGravity into the OpenMP worker and other caller; there is no standalone nbGravity symbol. from_binary rejects each of the five requested extractions. Functional and simulate are not run without a kernel. These variants are unqualified, not claimed to change numerics. Adding no-inline or keep-inline flags would change the experiment or measure an unused copy. Their full card binaries are left for review.
- V0/V3 whole-function extraction succeeds, but simulate rejects the undeclared cold nbReportTreeIncest call before execution. Including the report routine and fprintf@plt is also refused by the installed adapter: indirect-transfer aggregate functional coverage remains false despite its S14-20 handling. Both variants therefore still need the ticket-permitted S1-05 cold-error cut. Each retains all 202 preceding binary records unchanged plus an exit sentinel. All ten traces show that the sentinel is absent and normal return executes. No guessed stub cost or arithmetic rewrite is used.
- All five frozen-profile batches rank only the two all-input passing variants. Each has the same scenario, one-body/one-context call unit, and card-7120-measured hash. Automatic queue generation is disabled; the required two explicit prepare-native calls follow. Their cycle figures are unvalidated_scenario_estimate. The batch bound-gap diagnostic inherits S14-27 and is not used as a valid timing floor.
- schedule --method list on the actual V0 tree-walk loop is refused with "explored region contains an interior label" before searching. Interior labels and branches are preserved. No reorder gain is invented.
- prepare-native is attempted for V0 and the batch-selected nonbaseline nominee V3. Both refuse the original sparse captured address space, which exceeds the contiguous native-export 32 MiB image limit. No successful native request is claimed. Full linked binaries remain in build/flags/V0 through V3; bundled runtimes are in dist/card. scripts/flags-card-commands.sh prints the whole-application A/B commands and twin/flags/run-native.sh contains them for the lead. No printed command was executed.
