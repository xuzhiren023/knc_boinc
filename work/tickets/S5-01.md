# S5-01 knc-twin ranking of compile-flag variants for the gravity kernel

Sprint 5 (speed on the card, twin first; the card is busy). Depth: medium. knc-twin at ~/.claude/skills/knc-twin
(0.4.x; read `references/handoff-prompt.md`). No card access.

## Why
The card run (docs/sprints/sprint-1.md) is bit-identical to x86 but slow on small/medium. Before any card A/B, rank
cheap compiler-side options for `nbGravity` (the per-body tree walk; `x87_serial` and `resource` bind in S1-06).

## Rules
- Every variant must keep the project's numerics: no `-ffast-math` or its parts, keep `-ffp-contract=off`,
  `-fno-math-errno` and crlibm. A variant counts only if its twin `functional` output equals the x86 bits.
- Known twin defect: x87 double rounding (gcc-knc S14-37, `twin/x87-rounding-repro.json`) makes some bodies differ
  by 1 ULP. Use inputs that pass on the baseline: the S1-05 small capture and large-case bodies 0, 128, 256, 384
  (S1-06/S1-07 tooling). Say which inputs, and exclude none after seeing results.
- Same profile (`card-7120-measured`), scenario and unit of work for all variants; rank with `batch`, not by hand.

## Do
1. Variants (at most 6, rebuild only `nbody_grav.c` per variant; link the rest unchanged): V0 the current flags;
   `-O3`; `-mphinix -ffp-contract=off`; `-O2 -funroll-loops`; plus up to two of your choice from
   `C:/Users/xuzhi/Documents/gcc_knc/docs/gcc-knc-flags.md`, each with one line on why. If a variant changes
   numerics, record it and drop it.
2. For each: from_binary extraction (S14-20 is on main: no region cut needed now; say if any variant still needs
   one), `functional` on the inputs above, `simulate`, then `batch` over all passing variants.
3. Run `schedule` on V0's hot loop (beam or list) to see how much a reorder could gain under the model; report it
   as the twin reports it.
4. `prepare-native` requests (no card) for the top variant vs V0, so the lead can A/B on the card later.
5. Write `docs/twin-flags.md`: table of variant, functional status, predicted cycles per call, change vs V0,
   result_class, limiting constraints; the winner only if it beats V0 by more than the validated error, otherwise
   say "too close for the twin".
