# S11-02 Plug-and-play installer for the BOINC package (no command line)

Sprint 11. Depth: medium. No card access. Host load cap: 4 cores. Never write to `C:/ProgramData/BOINC` or start/stop
the owner's BOINC client while developing or testing; test against a fake BOINC data directory.

## Why
Owner 2026-11-17: "I want a plug and play solution, not a CLI solution." Today the owner installs with
`scripts/install-boinc-package.ps1` from a PowerShell prompt, stops/starts BOINC by hand and copies files by command.

## Do
1. A release folder/zip `dist/knc-boinc-installer/` with one double-click entry point (e.g. `Install KNC BOINC.cmd`
   that relaunches itself elevated via UAC, then runs a PowerShell script hidden) and a matching `Uninstall` /
   `Restore backup` entry point. Windows-only, no extra runtime downloads.
2. The installer: checks prerequisites (BOINC installed and attached to MilkyWay, the MilkyWay project folder, the
   card reachable over ssh with the configured key and known_hosts, the package check); shows what it will do in a
   simple dialog (Windows Forms MessageBox or equivalent) and asks to continue; stops BOINC gracefully
   (`boinccmd --quit`, wait for exit; never kill running science without asking); backs up the BOINC data directory;
   installs or updates the package (an update replaces the binaries and keeps the config); writes
   `knc_wrapper.cfg` and `app_config.xml`; starts BOINC Manager again; shows a final dialog with the result and the
   backup path. Existing foreign `app_info.xml`/`app_config.xml`: stop with a clear dialog, change nothing.
3. Uninstall/restore: removes our files and configs or restores the chosen backup, with BOINC stopped the same way.
4. A log file next to the installer for every run.
5. Tests: the script logic against a fake BOINC data tree (install, update, refuse foreign manifests, uninstall,
   restore), without touching the real BOINC directory; dialogs replaceable by a test switch.
6. `docs/TRY-IT.md`: replace the command steps with the double-click steps (keep the commands in an appendix).

## Accept
- The installer folder, test output, TRY-IT section and the Effort line in the Engineer report.

## Engineer report

Implemented the Windows double-click installer in `packaging/installer/` and assembled
`dist/knc-boinc-installer/` (approximately 55 MiB of package files). Entry points:
`Install KNC BOINC.cmd`, `Uninstall KNC BOINC.cmd`, and `Restore KNC BOINC backup.cmd`.
The launchers request UAC and run Windows PowerShell hidden. A settings form and
confirmation/result dialogs replace command entry. Each launch/operation writes a
unique dated log beside the installer; backups live in its `backups/` subfolder.
No extra runtime downloads or Python are required on the installing computer.

Installation checks BOINC executables, MilkyWay attachment/project folder, the
package contract/inventory using the native PowerShell counterpart of
`packaging/check_package.py`, and strict batch SSH with the configured key and
known_hosts (expects `k1om`). It requests `boinccmd --quit`, waits up to 90 seconds,
and refuses to kill a process. Windows boinccmd changes cwd to its registry data
folder, so shutdown explicitly supplies the selected data directory's RPC
credential without logging it. It copies the full data tree, including hidden
files and empty directories, before mutation. Updates replace recorded package
files and preserve `knc_wrapper.cfg` bytes. The installer writes the wrapper
config and one-task `app_config.xml`; manifest hashes and an ownership inventory
protect foreign/modified manifests. Uninstall removes recorded files only.
Restore verifies a selected full backup's identity/file checksums and saves a
current-state safety backup before replacing data. Failed mutations attempt full
rollback while the client is stopped. Linked/junction trees and overlapping
backup/data paths are refused. Restart is requested through the interactive
Explorer desktop (and the existing BOINC service when present), avoiding an
elevated interactive client.

`docs/TRY-IT.md` now starts with the double-click workflow; the former commands,
offline sample and detailed checks remain in an appendix. Source assets are
reviewable in `packaging/installer/`; `scripts/make-boinc-installer.sh` reproduces
the generated release folder. No upstream patches or compiler/performance changes
were needed, so no new patch class or compiler reduced repro applies.
