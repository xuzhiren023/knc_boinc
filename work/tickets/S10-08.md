# S10-08 TCP upload path for our card_run; fix the recovery tool's card check

Sprint 10. Depth: light. No card access by the engineer (the lead runs card jobs). Host load cap: 4 cores.

## Why
Owner 2026-11-17: "if DMA doesn't work use TCP". Today DMA failed three times (helper deadline, cleanup uncertain)
under laptop load and latched the card for both projects; ssh uploads run at ~20 KB/s (a 48 MB job takes ~40 min).
Lead measurement 17:34Z: the card pulling a 32 MB file from a host socket with busybox `nc 192.168.1.99 PORT > file`
received all 32,323,605 bytes in under one second. Card busybox 1.19.4 `nc` has no `-l` (client only), so the card
connects to the host. Host mic-side address: 192.168.1.99 (Ethernet); card 192.168.1.100 (mic0).

## Do
1. `--transfer tcp` in `tools/card_run`: for each upload, the host opens a listening socket on the mic-side address
   (ephemeral port, bound only to that address, accepting exactly one connection from 192.168.1.100, short accept
   timeout), and the card side runs `nc HOST PORT > <private staging file>` inside the guarded run dir; then the usual
   publish step. Integrity: byte length only (owner rule: no checksum on host-card transfers). Downloads (collect) may
   stay ssh unless large.
2. Transfer policy: `auto` = files below the threshold by ssh, larger by DMA; if DMA is unavailable before an endpoint
   opens (preflight), use TCP instead of ssh. After DMA data starts, an uncertain cleanup still stops and latches
   (shared rule). Add `--transfer tcp-large` (ssh below the threshold, TCP at or above) so the lead can avoid DMA
   entirely while the laptop is loaded. Document both in tools/CARD_RUN.md.
3. Fix `tools/card_dma_recover.py`: its card check failed with exit 2/255 while a plain ssh check worked (17:30Z);
   reproduce against the busybox shell (no bash features), fix, and test with the fake transport.
4. `tools/codex_run.sh`: launch the Codex engineer pinned to logical CPUs 0-9 (owner: leave CPUs 10-11 free for DMA
   helpers; children inherit the affinity), e.g. via `cmd //c start //b //wait //affinity 3FF ...` or PowerShell;
   do not edit codex_run.sh while another engineer session runs from it (bash reads it as it goes): write the change
   and say so; the lead installs it between sessions.
5. Tests with the fake transport: TCP routing by size and policy, length check failure, accept timeout, fallback
   only before DMA endpoints open; existing card_run tests still pass.

## Lead note (firewall, 2026-11-17)
Card-to-host TCP connected at 17:34Z (python listening on 192.168.1.99). The GCC-KNC lead reports that in their
earlier study Windows Firewall blocked inbound TCP from the card, so their tools have the host open every connection.
Here: the mic-side adapter "Ethernet" shows no network connection profile; the firewall is enabled for Domain,
Private and Public; which rule (e.g. an allow rule for python.exe) let the connection through was not determined
(rule enumeration needs admin). Whether inbound is allowed is the owner's setting: the tool must never change
firewall rules. So: detect a refused or timed-out card connection and fall back to ssh with a clear message, and
note in CARD_RUN.md that the TCP path depends on the owner allowing inbound TCP from 192.168.1.100.

192.168.1.99 on an ephemeral port, accepts once with a maximum five-second wait,

the guarded SSH file command into a private staging file. Byte count and nc exit
are checked before the existing guarded publication; no checksums or firewall
changes. Generated controls, packs, and TCP collection-helper bootstrap obey the
