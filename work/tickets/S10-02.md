# S10-02 Force walk on the card: find and close the 4-5x gap (forces bit-identical)

Sprint 10. Depth: deep. No card access. Laptop load light. Use the knc-optimize method (model first) and knc-twin
where it accepts the region.

## Why
Large case on the card (S9-06 build): whole 15.89 s, force walk (`nbMapForceBody`) 12.70 s. S8-08's counts for the
same run: 1.09e9 node visits, 8.9e8 interactions, 4.4e10 FP64 ops; modelled x87 issue floor ~1.6-2.5 s, all-cold
memory latency ~2.9 s (`.work/S8-08/docs/research/s8-force-model.md`, merged as `docs/research/s8-force-model.md`).
Measured 12.7 s leaves a 4-5x gap. S8-08's copy-into-walk-order layout was slower (+58%) because of the copy and
scatter; prefetch alone was never measured. The vector walk (S6-03) gave ~2%.

## Do
1. Measure what the walk spends, on the card, cheaply: a timers/counters build (option `WALK_PROFILE`, off by
   default) that records per-thread walk time, nodes visited and interactions per thread (load balance across 240
   threads, dynamic schedule chunk 4), and a variant with `schedule(dynamic,1)` / `guided`. Stage these as card jobs
   with predictions.
2. Read the emitted card assembly of the walk (`nbGravity` and its callers) and report: x87 stack shuffles (fxch),
   spills, memory-operand serialization, sqrt/div chains, branch layout. Put compiler-side findings in the report as
   "Compiler items" with a reduced repro (they go to GCC-KNC).
3. Exact app-side candidates (each behind its own option, results bit-identical): in-place guarded prefetch of the
   next nodes (no copy); a hot-field layout of the tree cells built inside the pool at tree time (positions, mass,
   rcrit, quad adjacent; no per-step copy); and anything the measurements point to. Rank on the host and, where it
   accepts the region (nbGravity converts fully per S9-03; bind a captured tree), with knc-twin; record predictions.
4. Card binaries on the release options from S10-01 (or S9-06's if S10-01 is not ready), knc_lint, a window script of
   <= 8 jobs (large; one core-small), predictions recorded before the card run.
5. x86 proof for anything selected: compare bit-identical on small/medium/large at 1 and 12 threads.

## Accept
- Measurements plan, assembly findings, compiler items, binaries, window script with predictions, proof output and
  the Effort line in the Engineer report.


## Engineer report

Implemented the force-walk experiments and staged the card measurement window.
No card job was run. The 4-5x gap is **not proven closed**: the applicable twin
sample predicts changes of only -3.2% to +0.7%, and the native profiles are pending.
All three exact application candidates pass the full requested x86 matrix.

Changes:

- `WALK_PROFILE=1` (default 0) records actual per-thread `nbGravity` time,
  active-loop duration before the barrier, bodies, nodes, interactions and
  accepted cells. Counters accumulate locally, then in TLS; rows include idle
  threads and actual team size. The dynamic4, dynamic1 and guided4 builds are
  separate from uninstrumented candidate timings. Two clock reads per target,
  counters, code layout and output perturb the profile; compare against baseline.
- `WALK_PREFETCH=1` (default 0) issues guarded in-place successor hints. More is
  evaluated only for cells; null pointers are excluded. No packing/scatter.
- `WALK_HOT=1` (default 0) puts mass/rcrit beside position and the quad block
  immediately after the common node. Tree/pool construction writes this layout
  directly. Node/body/cell sizes stay 64/96/160 bytes. Mass/rcrit/quad/More
  offsets change from 40/64/80/72 to 32/40/64/128. The later More link can hurt;
  there is no assumed layout win. Body checkpoint offsets change: restart with
  the same option set. Science grouping, tree ordering and force ordering stay
  unchanged.
- `WALK_SCHEDULE=1` selects dynamic1; 2 selects guided with minimum chunk 4;
  default 0 retains existing scheduling. Only the scalar tree force loop changes.
- `WALK_PROOF=1` is test instrumentation for full xyz byte streams and tree
  capture. Default 0; every card candidate has it disabled.

The two new patches are exclusively **Performance**
(`zzzzz-nbody-walk-performance.patch`) and **Instrumentation**
(`zzzzzz-nbody-walk-profile.patch`), documented in `patches/README.md`.
The three new helper headers keep those classes separate. No compiler scheduling,
vectorization, reciprocal or arithmetic rewrite is implemented in the app.

Build configuration: S10-01 release.env was absent when this experiment was
configured, so the ticket's S9-06 fallback is used: O2, TREE_VARIANT=4,
PARALLEL_QUAD=1, STATIC_INTEGRATE=1, FORCE_CHUNK=4, DF_REUSE=0,
VECTOR_GRAVITY=0, WALK_LAYOUT=0, TREE_IDENTITY=0, WALK_COUNTERS=0.
PHASE_TIMERS=1 matches S9-06's measured build. WALK_PROFILE is enabled only in
its three diagnostic variants. Builds use make -j2 and the pinned Cygwin/KNC
compilers, with TMPDIR/TMP/TEMP exported to this worktree's build/tmp before
compilation. Same-HOT objects unaffected by gravity-only defines are reused
within this build; gravity is always compiled for the requested variant. No
Git writes, downloads, installs, or writes to gcc_knc were performed.

### Compiler items

For GCC-KNC follow-up; these are investigation items, not asserted compiler bugs
or measured speedups. Reduced repro: `probes/s10_walk_scalar.c`; rerun
`bash scripts/s10-walk-compiler.sh`. Output: `compiler-repro.o`,
`compiler-repro.dis`, `compiler-repro-missed.txt` under build/s10-walk.

- nbGravity has 199 in-symbol decoded instructions, 6 fxch sites, 29 FP stack
  accesses, 54 FP memory-operand sites, one fsqrt and four divide sites. Its frame
  is 0x68 bytes. Target xyz, accumulators and quad intermediates occupy stack
  slots. Investigate scalar double off x87, register allocation and stack reuse.
  These accesses include deliberate binary64 roundings; not all are proven
  avoidable spills. Instruction counts exclude inter-function alignment bytes.
- Every accepted interaction rebuilds an indexed eps2 stack array, including two
  unconditional load/store pairs. Target type reloads too. Investigate invariant
  hoisting and scalar replacement in the reduced repro instead of hand-changing
  the app's FP sequence.
- Softened distance -> fsqrt -> mass/r -> phi/d is a serial chain; quad adds two
  divides. Investigate legal scheduling of independent work and x87 memory-form
  serialization. Preserve grouping, rounding and exceptions; no approximate
  reciprocal, sqrt or reassociation was used.
- Branch layout: loop 0x405077, backward cell opening test 0x405058; rejected
  cells pop four x87 values before More; accepted nonself paths enter arithmetic;
  no-quad/body paths have duplicated cleanup before Next; self/incest paths are
  cold. The complete cold nbReportTreeIncest call remains in the twin but is not
  executed. The outlined caller has 296 decoded sites, 5 fxch and 82 stack FP
  accesses, plus external-potential and OpenMP calls. See `assembly.json` and the
  three retained disassemblies for addresses/bytes and caller findings.
