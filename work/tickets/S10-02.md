# S10-02 Force walk on the card: find and close the 4-5x gap (forces bit-identical)

Sprint 10. Depth: deep. No card access. Laptop load light. Use the knc-optimize method (model first) and knc-twin
where it accepts the region.

## Why
Large case on the card (S9-06 build): whole 15.89 s, force walk (`nbMapForceBody`) 12.70 s. S8-08's counts for the
same run: 1.09e9 node visits, 8.9e8 interactions, 4.4e10 FP64 ops; modelled x87 issue floor ~1.6-2.5 s, all-cold
memory latency ~2.9 s (`.work/S8-08/docs/research/s8-force-model.md`, merged as `docs/research/s8-force-model.md`).
Measured 12.7 s leaves a 4-5x gap. S8-08's copy-into-walk-order layout was slower (+58%) because of the copy and
scatter; prefetch alone was never measured. The vector walk (S6-03) gave ~2%.

## Do
1. Measure what the walk spends, on the card, cheaply: a timers/counters build (option `WALK_PROFILE`, off by
   default) that records per-thread walk time, nodes visited and interactions per thread (load balance across 240
   threads, dynamic schedule chunk 4), and a variant with `schedule(dynamic,1)` / `guided`. Stage these as card jobs
   with predictions.
2. Read the emitted card assembly of the walk (`nbGravity` and its callers) and report: x87 stack shuffles (fxch),
   spills, memory-operand serialization, sqrt/div chains, branch layout. Put compiler-side findings in the report as
   "Compiler items" with a reduced repro (they go to GCC-KNC).
3. Exact app-side candidates (each behind its own option, results bit-identical): in-place guarded prefetch of the
   next nodes (no copy); a hot-field layout of the tree cells built inside the pool at tree time (positions, mass,
   rcrit, quad adjacent; no per-step copy); and anything the measurements point to. Rank on the host and, where it
   accepts the region (nbGravity converts fully per S9-03; bind a captured tree), with knc-twin; record predictions.
4. Card binaries on the release options from S10-01 (or S9-06's if S10-01 is not ready), knc_lint, a window script of
   <= 8 jobs (large; one core-small), predictions recorded before the card run.
5. x86 proof for anything selected: compare bit-identical on small/medium/large at 1 and 12 threads.

## Accept
- Measurements plan, assembly findings, compiler items, binaries, window script with predictions, proof output and
  the Effort line in the Engineer report.
