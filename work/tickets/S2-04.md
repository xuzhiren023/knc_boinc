# S2-04 Wrapper passes the real task contract through (command line and input files)

Sprint 2. Depth: standard. Depends on S2-02, S2-03 (merged).

## Why
S2-03 could not confirm the command line and file names of current MilkyWay N-body workunits. The wrapper must work
for whatever the server sends, not only our sample layout.

## Do
1. Pass-through: the wrapper forwards every command-line argument the client gives it to the card app, unchanged in
   order, except that any argument naming a file present in the slot (an open name the client resolves with
   `boinc_resolve_filename`, as in the 2024 forum example in docs/packaging.md: Lua parameters, histogram, output
   names) is staged to the card and rewritten to the remote path; output names are mapped back after the run.
   Arguments the wrapper itself needs (checkpoint, progress, snapshot options) are added, never replacing the task's.
   Upstream's own options that touch files (`-f`, `-h`, `-o`, `-z`, `--checkpoint` and the like: take the list from
   the pinned source's option table) are handled by rule, not by guessing from the value.
2. Tests: a fake-card run driven by a command line and slot layout shaped like the 2024 forum example (logical and
   physical names differ, extra numeric parameters after the file options), plus our sample workunit. Both must
   produce outputs under the resolved names. Keep the five S2-02 flows green.
3. `docs/wrapper.md`: the pass-through rules and what remains unknown about current workunits.

## Acceptance
- New tests fail first, then pass; S2-02 and S2-03 tests stay green.

## Engineer report

Implemented argument pass-through in `src/knc_wrapper.cpp`. Task argument order,
seed, numeric/Lua parameters and explicit thread/checkpoint settings are retained.
File rules follow the pinned `nbody/src/main.c` table: input-file, histogram-file,
match-histogram, histoout-file, output-file, checkpoint and visualizer-bin, with
short, attached-short and long/equal operand forms. Other existing positional
files are also resolved/staged. Remote names are private numbered paths, so
physical/logical name differences and input histogram/output name collisions do
not interfere with wrapper metadata. Outputs return through BOINC resolution;
soft-link placeholders remain intact. Wrapper defaults are prepended only when
absent, before positional parameters. Task-selected checkpoints work for quit,
restart and successful completion when upstream retains the checkpoint. The
zero-argument development invocation remains compatible with S2-02.

Added two real-x86/fake-card acceptance cases and fake-client argument support.
The forum-shaped case has distinct logical/physical names, a different seed,
trailing numeric parameters, an extra file parameter with a space, body/histogram
outputs and task-selected checkpoint quit/restart. The explicit sample case
uses long/equal options and returns a retained checkpoint. Both inspect the
actual supervisor argv as well as resolved outputs. Updated `docs/wrapper.md`,
removed the now-stale fixed-command limitation in `docs/packaging.md`, and
clarified the existing lead launcher's task-argument usage.
