## Why
First real BOINC task on the card (117676, 2026-11-17 22:11Z): the task runs correctly, but BOINC Manager and the
graphics show 0% for ~16-20 minutes while the 110,000 stars are generated (the app reports no fraction done and
writes no snapshot before the first step). The wrapper launches the card app with `--checkpoint-interval=1`
(seconds), so a 110,000-body task may write a ~21 MB checkpoint every second during the steps. And card time is
booked on the shared ledger by hand (`tools/card_turn.py`).

## Do

   generation by bodies done, the rest by steps; say how you weight it) and send a "Generating stars N / total"
   status to the graphics (the graphics app shows it instead of an empty view). Prefer an output the app already
   has or a small instrumentation patch (own patch class) that prints body count progress to a file the wrapper
   polls; no change to science results (likelihood bit-identical on core-small).
2. Checkpoint interval: measure on the host what `--checkpoint-interval=1` costs for 110k bodies; choose a sensible
   default for the card (BOINC's own checkpoint preference, or a fixed 60-300 s), make it a wrapper config key.
3. Automatic card booking: when a task starts, the wrapper queues a knc-boinc turn row on the shared ledger
   (`C:/Users/xuzhi/Documents/card-coordination/jobs.jsonl`, same row shape and rules as `tools/card_turn.py`:
   project knc-boinc, timingValid, queuedTime, 3-hour liveness with requeue) and waits until no earlier foreign job
   is live before starting the card program; it closes the row when the task ends, is suspended for a long time, or
   aborts. Never start while the shared DMA stop latch exists. Config key to turn it off.
4. Tests with the fake card/client harness (tests/wrapper.sh) for all three; package rebuilt.

### Measured checkpoint cost

`scripts/measure-checkpoint-cost.sh` exercises the actual upstream scheduler and checkpoint writer with 110,000 synthetic bodies (two real Body arrays), without generating/evolving a full task. `OMP_NUM_THREADS=4`; the writer is serial. Measurements:

| Interval | Observation | Writes | Bytes/write | Writer wall time |
| --- | --- | --- | --- | --- |
| 1 s | 10.010067 s | 5 | 21,121,408 | 0.147332 s |
| 120 s | 10.012475 s | 0 | No write observed | 0 s |

Interval 1 cost about **29.5 ms/write**, **1.47%** of the observation window. Upstream compares integer wall seconds using `>`, so interval 1 normally writes about every two seconds at safe steps. The 120-second default substantially reduces repeated 21 MB writes while bounding ordinary lost work to roughly two minutes plus a step. This is cached host filesystem/API cost, not a card or physical-disk durability measurement. Raw results: `build/s11/checkpoint-cost.txt`.
