## Why

## GCC-KNC lead's guidance (2026-11-17)
1. Cause: not established; most likely host load. "helper deadline" = the transfer helpers did not finish inside the
   staging budget (3.8 s ssh bootstrap on a loaded laptop, plus helper start and SCIF connect). card_run then cannot
   prove both endpoints closed and latches by design.
2. Card-wide (must stay shared): the DMA stop latch (both tools must see it; today
   `gcc_knc/.work/_state/card-dma-active.lock`), and no two tools may DMA at once (a card-wide DMA lock beside the
   latch). Per-tool: receipts, job locks, host staging (our own staging dir, not `gcc_knc/.work/_shared/claude-input-*`),
   card run-dir names (our own prefix, e.g. `/tmp/knc-boinc/`, so cleanup never touches the other tool's dirs).
3. Settings: `--transfer auto` already uses DMA only above `threshold_bytes` (1 MiB). Raise it to 64 MiB: small
   helpers (claude-pin, scripts) go over ssh, large inputs over DMA. Fallback to ssh is automatic only before any
   endpoint opens; after data starts, an uncertain cleanup must stop (keep that). On a loaded host raise the transport
   timeout instead of retrying.
4. Recovery (lead or owner signs off): (a) host `event_log()` (host_card_transfer.py) equals the latch's
   `host_state`; (b) no `claude-transfer.exe` on the host; (c) card boot_id equals the latch's boot_id and no
   claude-transfer process on the card; (d) remove that card run dir including `claude-dma-active`; (e) archive the
   latch file, then delete it. If (a) or (c) differs, clear nothing: a reboot may be needed (owner's call).

2. `tools/card_dma_recover.py`: steps (a)-(e) above, dry-run by default, prints each check; `--confirm` performs (d)
   and (e) only when (a)-(c) all pass; refuses otherwise. It never reboots anything.
3. Tests with the fake transport: per-tool paths, latch shared path unchanged, threshold routing (small file over
