# S9-04 Balanced tree build and parallel threadTree on the card (tree bit-identical)

Sprint 9. Depth: deep. No card access. Laptop load light (owner): `make -j2`, x86 identity runs at 12 threads on
small/medium/large only, no full 117676 runs, no timing sweeps.

## Why
Card, large case (20,000 bodies, 111 builds), S8-07 pool build (`TREE_VARIANT=2`), sub-phase seconds
(runs/card/w14/S8-07/tree-pool.txt): insertion 3.12, hackCofM 2.24, threadTree 1.80, hackQuad 2.48, partition 0.14,
expandBox 0.13; whole nbMakeTree 9.91 s of a 23.7 s run (force 12.7 s). The serial build is insertion 5.15,
hackCofM 2.37, threadTree 1.82, hackQuad 2.69. Parallel CofM/Quad barely helped: the depth-3 frontier is fixed, and
the Plummer core puts most bodies into a few depth-3 octants, so a few threads do almost all the work. threadTree is
still serial. Goal: nbMakeTree <= ~1.5 s on the card with an identical tree.

## Do
1. Adaptive frontier by body count (new `TREE_VARIANT=3`, built on S8-07's pool variant in
   `patches/nbody-tree-variants.patch`): split cells top-down, serially, until every frontier subtree holds at most
   about nbody / (k x threads) bodies (choose k; justify) or reaches the epsilon depth; cells above the frontier are
   created exactly where the serial code would create them. Then insertion, hackCofM and hackQuad run per frontier
   subtree in parallel (dynamic schedule, biggest first), and the levels above the frontier finish serially in the
   original octant order.
2. Parallel threadTree: thread each frontier subtree in parallel, then link subtree boundaries serially so every
   Next/More pointer equals the serial result.
3. Identity: S8-02/S8-07's every-step tree identity checker (shape, Pos, Mass, Rcrit2, Quad, Next/More walk) on small,
   medium and large at 1 and 12 threads; `scripts/compare.py` bit-identical against the references.
4. Card binary `build/s9/card-tree3/milkyway_nbody.mic` with the S9-01 base options plus `TREE_VARIANT=3`
   (`PARALLEL_QUAD=1 STATIC_INTEGRATE=1 PHASE_TIMERS=1 VECTOR_GRAVITY=0 FORCE_CHUNK=4`, O2) and the tree sub-phase
   timers; knc_lint; card commands (large + core-small) for `tools/card_run` (this repo's runner) in the window-script
   form. Predict the card sub-phase times with a short model (frontier balance from the x86 counts).
5. Performance patch behind the option, in its own patch file (AGENTS.md patch classes).

## Accept

## Engineer report

Implemented S9-04 offline in the ticket worktree. Changes are uncommitted for

- Added `patches/nbody-tree3.patch`, class Performance, selected by
  TREE_VARIANT=3; the source default remains 0. Stable serial octant partitioning
  stops at max(2, nbody/(4*threads)) bodies or epsilon depth. Singleton groups
  attach bodies directly; colliding groups create the same cells and midpoint
  coordinates as serial insertion. Insertion, CofM and Quad use largest-first
  frontier jobs with dynamic scheduling. Persistent scratch is released with
  the existing pool ownership lifecycle.
- Chose k=4 to leave several jobs per worker as subtree costs vary, while
  avoiding individual-body jobs on large. Octant splitting undershoots the cap:
  the prospective large/card frontier averages 3,044 jobs (12.7 per worker),
  rather than exactly 960. The minimum of two retains a real collision subtree
  on tiny cases. This choice used no timing sweep.
- Upper cells finish serially in octant postorder; each cell preserves the
  original arithmetic order. Parallel threadTree gives each subtree local NULL
  boundaries. Reverse postorder links the upper tree; serial repair sets every
  final-child-spine successor to its external boundary, including cell Next
  pointers and the final body's Next. More and all boundaries are compared with
  serial on every successful build.
- Regenerated `zz-nbody-tree-instrumentation.patch` separately, retaining the
  checker/timers and adding frontier/model counts under TREE_IDENTITY=1.
  Card TREE_IDENTITY=0 excludes these count diagnostics. Both patches have
  exactly one class in patches/README.md; the new Performance patch contains
  no instrumentation hooks.
- Added scripts/build-tree3.sh, scripts/s9-tree3.py, scripts/test-tree3.sh and
  tests/test_s9_tree3.py. The build script stages runtimes and prints the two-job
  window script. The test entry point supplies the Cygwin runtime PATH.
  An initial manual host launch lacked that PATH and exited 0xC0000135 before
  main; all six retained proof runs used the corrected environment and exited 0.
- fetch.sh now verifies the complete patched state by replaying pinned blobs
  before testing individual hunks. Later algorithm/instrumentation patches
  overlap earlier hunks, so individual reverse dry-runs cannot recognize the
  final source. Pristine sources retain the normal forward application path.
  Existing sources passed the no-download idempotent fetch rerun.

Short model: assign descending job body counts to the least-loaded of 240
workers (LPT). Parallel insertion/CofM/Quad cost is S8-07 pool seconds times
new/old critical-body load. Add original serial CofM/Quad seconds times
new_top/total_cells and 0.02 seconds per phase for dispatch/barriers across all
111 builds. threadTree uses
1.82*(top/cells+(1-top/cells)*new_critical/20000)+0.02. expandBox retains 0.13.
Partition conservatively costs
0.14*(2*new_body_visits+new_top)/(40000+old_top), calibrated by the old two
serial passes. Formulas/samples: build/s9/tree3-model.json; short prediction:
build/s9/tree3-prediction.txt. No model table was used.

The estimate is about 2.13 seconds, above the ~1.5-second goal; serial partition
is the main remaining risk (~1.53 seconds). This count model is not a native
measurement. Subtree depth, cache/x87 effects, slab atomics, boundary repair and
runtime overhead may change it substantially. Do not score this as demonstrating
the timing goal. No compiler optimization issue was established: this is
