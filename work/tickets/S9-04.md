# S9-04 Balanced tree build and parallel threadTree on the card (tree bit-identical)

Sprint 9. Depth: deep. No card access. Laptop load light (owner): `make -j2`, x86 identity runs at 12 threads on
small/medium/large only, no full 117676 runs, no timing sweeps.

## Why
Card, large case (20,000 bodies, 111 builds), S8-07 pool build (`TREE_VARIANT=2`), sub-phase seconds
(runs/card/w14/S8-07/tree-pool.txt): insertion 3.12, hackCofM 2.24, threadTree 1.80, hackQuad 2.48, partition 0.14,
expandBox 0.13; whole nbMakeTree 9.91 s of a 23.7 s run (force 12.7 s). The serial build is insertion 5.15,
hackCofM 2.37, threadTree 1.82, hackQuad 2.69. Parallel CofM/Quad barely helped: the depth-3 frontier is fixed, and
the Plummer core puts most bodies into a few depth-3 octants, so a few threads do almost all the work. threadTree is
still serial. Goal: nbMakeTree <= ~1.5 s on the card with an identical tree.

## Do
1. Adaptive frontier by body count (new `TREE_VARIANT=3`, built on S8-07's pool variant in
   `patches/nbody-tree-variants.patch`): split cells top-down, serially, until every frontier subtree holds at most
   about nbody / (k x threads) bodies (choose k; justify) or reaches the epsilon depth; cells above the frontier are
   created exactly where the serial code would create them. Then insertion, hackCofM and hackQuad run per frontier
   subtree in parallel (dynamic schedule, biggest first), and the levels above the frontier finish serially in the
   original octant order.
2. Parallel threadTree: thread each frontier subtree in parallel, then link subtree boundaries serially so every
   Next/More pointer equals the serial result.
3. Identity: S8-02/S8-07's every-step tree identity checker (shape, Pos, Mass, Rcrit2, Quad, Next/More walk) on small,
   medium and large at 1 and 12 threads; `scripts/compare.py` bit-identical against the references.
4. Card binary `build/s9/card-tree3/milkyway_nbody.mic` with the S9-01 base options plus `TREE_VARIANT=3`
   (`PARALLEL_QUAD=1 STATIC_INTEGRATE=1 PHASE_TIMERS=1 VECTOR_GRAVITY=0 FORCE_CHUNK=4`, O2) and the tree sub-phase
   timers; knc_lint; card commands (large + core-small) for `tools/card_run` (this repo's runner) in the window-script
   form. Predict the card sub-phase times with a short model (frontier balance from the x86 counts).
5. Performance patch behind the option, in its own patch file (AGENTS.md patch classes).
