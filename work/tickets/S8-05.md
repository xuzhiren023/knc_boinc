# S8-05 Vectorized mixed-dwarf distribution function with exact fallback on near-ties (bodies bit-identical)

Sprint 8. Depth: deep, fast turnaround. No card access. Deadline: a card binary and the x86 proof within 75 minutes
of start (card window closes 02:59Z). Independent of S8-03 (which parallelizes the same nodes exactly, in
`.work/S8-03`): start from main, do not edit S8-03's files; you may read them.

## Why
Real workunit 117676 spends ~4,560 of ~5,490 laptop seconds in serial body generation (`nbody_mixeddwarf.c`:
`vel_mag` :587 -> `max_finder` / rejection loop -> `dist_fun` :465 -> `gauss_quad` :94 -> ~330 calls of `fun` :364).
One card thread runs this x87 code ~12x slower than a laptop core. `dist_fun` only decides accept/reject and the
`max_finder` comparisons: a body's r and v come from the random stream, not from `dist_fun`. So `fun` may be computed
fast (vector lanes, reassociated, vector math) as long as every decision that depends on it comes out as the exact
code would decide it. Then the generated bodies are bit-identical and the likelihood is unchanged.

## Design (required)
1. Fast path, compile option `NBODY_FAST_DF` (off by default; on for the card build and an x86 test build): compute
   the `gauss_quad` node values with a vectorizable loop over nodes (8 doubles per IMCI vector on the card; let
   GCC-KNC vectorize it, or check `-fopt-info-vec`; if a callee's math function blocks vectorization, say which and
   what GCC-KNC offers). Combine with an OpenMP parallel for over node blocks when not inside a parallel region.
   Node positions come from the original serial recurrence, unchanged.
2. Error bound per `gauss_quad` result: the fast sum S_fast must carry a rigorous absolute bound E on |S_fast -
   S_exact| (e.g. sum of |terms| times a stated relative error per node value plus summation error). State the
   per-node error assumption and how it is justified (measured max ULP difference of fast vs exact `fun` over the
   real inputs is evidence, not a bound: say which you use, and add a safety factor of at least 1e3).
3. Guarded decisions: every comparison that uses a `dist_fun` value (`max_finder` comparisons, `mw_fabs(d /
   dist_max) > u`, any other) is decided by the fast values only if it holds with margin larger than the propagated
   bound; otherwise restore the dSFMT state saved at the start of that body's `vel_mag` and recompute that body's
   `vel_mag` with the exact upstream code. Count fallbacks.
4. Proof on x86: dump all generated bodies (positions, velocities, masses, in order) for the core-small case from
   S8-03 if it exists (`.work/S8-03/workunits/core-small/`), otherwise make one the same way (copy of
   `.work/S7-02/runs/real/inputs/EMD_v196_OCS_north_orbit_core_fitting_110k_bodies.lua`, ~4,000 bodies, short
   evolve), and for the full 110,000-body generation of 117676 (generation only: stop after the bodies are made, or
   compare the first checkpoint), fast vs unmodified: byte-identical. Likelihood of core-small bit-identical
   (`scripts/compare.py`). Report fallback counts and generation seconds on x86 at 12 threads, fast vs unmodified.
5. Card build `build/s8/card-fastdf/milkyway_nbody.mic`: S7-01 scalar card flags (chunk 4, `VECTOR_GRAVITY` off) plus
   `NBODY_FAST_DF`; include the S8-01 timer patch (on main) and, if present and finished, S8-02's parallel tree
   (`.work/S8-02/patches/nbody-parallel-tree.patch`, `PARALLEL_TREE=1`). Passes `knc_lint`. Print the card_run
   commands (window-script form: `--benchmark --threads 240`, the three `dist/card` runtimes,
   `scripts/card-launch.sh OMP_NUM_THREADS=240 ... --nthreads 240 ...`) for core-small with the real 117676 argument
   list.
6. If time remains (optional, after 1-5): knc-twin on the node kernel, scalar vs fast, one core with four contexts
   (`card-7120-measured`), from the card binary; report status, cycles per node and result_class.

## Accept
