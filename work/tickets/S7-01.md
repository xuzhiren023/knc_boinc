# S7-01 Re-pin to N-body 1.96, the version MilkyWay@home's standard N-body app runs

Sprint 7 (owner 2026-11-16: run an optimized N-body on the card, submit at least one task, pass validation).
Depth: medium. No card access.

## Why
milkyway.cs.rpi.edu/milkyway/apps.php (read 2026-11-16): "N-Body Simulation" is **1.96** on every platform
(Windows x86_64 1.96 and 1.96 mt, built 3 Jun 2026). 1.97, our current pin (`d78c48fc`), is the separate "N-Body
Simulation with Orbit Fitting" app. To pass validation against other hosts' results our build must compute what the
1.96 app computes. Upstream tag `nbody_1.96` = `1e640779f1cabf88aaa49e4db569cfe7e09016c4`; the lead cloned it to
`third_party/milkywayathome_client_196` (submodules not fetched; our build does not use them).

## Do
1. `git diff nbody_1.96..nbody_1.97` summary for `nbody/`, `milkyway/` and the math code: list every change that can
   alter results, file formats, command-line options or workunit parameters.

   source lists, `config/` header (version 1.96). `app_info.xml`: app name `milkyway_nbody`, version_num 196,
   platform windows_x86_64. Keep 1.97 support out unless it is free.

   knc_lint, package checks, and all offline tests pass (expected failures named as before). Vector gravity (macro
   on) and chunk 4: x86 bit-identical to macro off on 1.96, as in S6-03.

### Upstream comparison: 1.96 to 1.97

Compared pristine objects, not either patched working tree. The two supplied
clones are shallow and each has only its own version's tags. A read-only
alternate object database exposes the 1.96 object to the 1.97 repository:

```bash
export GIT_ALTERNATE_OBJECT_DIRECTORIES="$PWD/third_party/milkywayathome_client_196/.git/objects"
git -C third_party/milkywayathome_client diff \
  1e640779f1cabf88aaa49e4db569cfe7e09016c4..nbody_1.97 \
  -- nbody milkyway crlibm dSFMT lua
```

This is `nbody_1.96..nbody_1.97` by commit identity. Raw diff:
`build/upstream-196-to-197.diff`; 108 files, 6,800 insertions / 1,572 deletions.
No changes to crlibm, dSFMT or Lua itself. Every functional category found:

- **Softening, body/context/checkpoint layout:** `nbody_types.h`, defaults,
  `nbody_lua.c`, `nbody_lua_types/nbody_lua_nbodyctx.c`, shared Lua marshal
  header/source and `nbody_grav.c`: fixed `eps2[3]` becomes allocated square
  `eps2` plus required `eps2_index`/`eps2_size`, cached per-body `eps2Index`,
  and `eps2_min` for cells. 1.96 selects LM/cross/DM by summed node/body
  types (cells included); 1.97 uses a type-index matrix for bodies and minimum
  softening for cells, including in the exact-force path. Lua gains size_t,
  dynamic real/int arrays, validated table lengths and getters/setters.
  Bodies with unlisted types now fail setup. `NBodyCtx` also adds
  `samplingBounds[2]`; defaults correct the position of `calibrationRuns`.
  These struct changes alter raw checkpoint/capture layouts even though
  `nbody_checkpoint.c` itself is unchanged. Cross-version checkpoints must
  not be reused. 1.96 serializes its fixed softening values inline.
- **Math and platform numerics:** `milkyway_math_double.h`, new
  `milkyway_math_funcs.{h,c}` and its CMake list replace system `erf`, `cbrt`,
  `tgamma`, `lgamma` with bundled CORE-MATH. The float header instead changes
  cbrt to `mw_pow(x,1/3)` and removes a duplicate gamma macro. `nbody_friction.c`
  switches direct `erf`/`exp` to `mw_erf`/`mw_exp`, affecting LMC friction
  (including crlibm selection). `nbody_math_funcs.{h,c}` moves the ODE solver,
  gamma/error routines, derivatives and quadrature out of king/mass/mixed
  dwarf sources. Derivatives now use forward five-point stencils near the
  origin instead of probing negative radius; the centered stencils remain
  away from zero. Quadrature changes truncated decimal weights/nodes to
  `5/9`, `8/9`, and `sqrt(3/5)`, enumerates nodes, evaluates integrands in an
  OpenMP static loop, then sums in the original order; new allocation failure
  paths return zero. Thus its arithmetic changes as well as its parallelism.
  `gammln` adds a thread-local memo check initialized at z=-1e308/value=0;
  the tag never updates that cache, so that sentinel gets a new early return.
  `gammq` now rejects NaN arguments through an ordered nonnegative/positive
  test. Other relocated gamma/error formulas and ODE steps are unchanged.
  Their new translation unit includes nbody_config.h, so
  relocated code uses the N-body math configuration (the old King source did
  not include it). King callback arguments become const. Build lists add the
  two new math translation units; N-body version changes to 1.97.
- **Dwarf initialization, density/potential and mass:**
  `nbody_potential_types.h`, `nbody_lua_types/nbody_lua_dwarf.c`,
  `nbody_dwarf_potential.c`, `nbody_mixeddwarf.{h,c}`: constructors now call
  `set_model_params` eagerly; lazy initialization disappears from potential,
  density and King radius queries. NFW characteristic density consistently
  uses `ps` while `p0` denotes cored central density. Truncated NFW/cored
  formulas cache `mcut_pref` and `const_gamma_func` (replacing `gamma1`),
  changing floating-point evaluation order. Einasto gains implemented
  half-mass-radius conversion (`d`, `h`), mass normalization, corrected
  density/potential (including the sign between incomplete-gamma terms),
  enclosed mass, peak-density radius and 99.9%-mass sampling bound.
- **Sampling/workunit API:** mixed-dwarf generation accepts optional
  `samplingBounds` (also in context); omitted bounds reset to zero defaults.
  It rejects inconsistent zero mass/body-count components. Default Plummer
  bound changes from `50*(rscale_l+rscale_d)` to `38.71369177075227*rscale`
  per component; general Hernquist to `198.49874371066198*rscale`; truncated
  NFW/cored from `rcut+15*rdecay` to a density-based log cutoff; untruncated
  NFW/cored remain `5*r200`. King retains its tidal radius and mixed-King
  restriction when using automatic bounds. Particle masses now use enclosed
  mass at the sampling boundary for every profile without mutating the
  input component mass; old code recalculated only NFW/cored masses.
- **Timestep/softening helpers:** `nbody_lua_models.c` changes
  `calculateTimestep(mass,radius)` to `calculateTimestep(comp1,comp2)` using
  enclosed component masses, the densest structural scale (King r0), and
  one-component branches. The old formula is renamed
  `calculateTimestepPlummerTest`. `calculateEps2Dwarf` additionally treats a
  zero component mass as a one-component case. Existing 1.97 Lua is therefore
  not a drop-in 1.96 workunit.
- **Likelihood:** `nbody_emd.c` initializes previously uninitialized
  accumulators, rejects unordered ranges including NaN, rounds EMD for each
  range, bounds/normalizes by actual first/last included lambda values instead
  of a hardcoded maximum 50, and sums per-range logarithmic penalties instead
  of a count-weighted combined EMD. `nbody_mass.c::nbCostComponent` adds
  range selection (Lua histogram ranges override data ranges; fallback full
  range; odd trailing endpoints discarded), per-range simulated/data counts,
  variance and summed penalties instead of a single global cost. `nbody.c`
  best-likelihood selection changes `abs(final)>abs(best)` to
  `!(abs(final)<=abs(best))`, so NaN final values can select the saved best.
- **Body file formats:** `nbody_io.c` outputs `# type` and signed `Type(p)`
  instead of `# ignore` and `ignoreBody(p)` (1.96: 0 light, 1 dark).
  `nbody_manual_bodies.c` recognizes a first-line `type` header, accepts
  arbitrary nonzero signed types and rejects tree-reserved zero; otherwise
  maps legacy 0/1 through BODY rather than assigning them directly.
  `nbody_particle_data.c` accepts both header names. Manual-body sample data
  changes to signed types and adds an explicit old-format example.
- **Shipped Lua parameters/test fixtures:** sample `for_developers`,
  `settings`, `settings_gui` change minimum version, use the new timestep
  helper and softening matrix/type map; developer settings add manual radial
  sampling bounds. `settings` and GUI fix the dwarf-softening call/three
  returns and maximum-softening table; their Coulomb parameter changes
  0.470003629 to 15. `settings`, GUI and `settings_gui_updated` change LMC
  position (-1.1,-41.1,-27.9) to (-0.52,-40.8,-26.5) and velocity
  (-57,-226,221) to (-58.2,-231,226). GUI creates component models before
  context evaluation and reuses them. Most test Lua (orphan/GPU/checkpoint,
  invalid, benchmark, context and mixed dwarf) adopts the new softening table
  and/or renamed old timestep helper; newhist files also have line-ending
  churn. `RunTestUnits.lua` replaces all eighteen stored 10,000-body reference
  likelihoods; e.g. model_1/670828913 changes 740.402856198082418 to
  690.718988733357037. These are not our 64/1024/20000-body baselines.
  The EMD range test updates its expected full-histogram score from
  5.449191188301354 to 23.388462440913543. Mixed-dwarf
  tests add profile-based timestep/default bounds, zero-mass/Einasto cases
  and sampling parameters; softening tests are updated and a multitype
  fixture/test is added. These are test/model changes, not new CLI switches.
- **Platform/build fixes:** `milkyway_cpuid.c` uses MSVC intrinsics only with
  MSVC, inline assembly otherwise, and explicit ANSI Win32 version APIs;
  `milkyway_rename.c` explicitly casts transaction entry points. Curses adds
  an `isatty` declaration fallback. These affect platform compilation/runtime
  paths rather than the scalar science formulas. `nbody/tests/CMakeLists.txt`
  adds the multitype softening test. `nbody/src/main.c` is identical between
  tags: no command-line option additions/removals or parser changes. The
  public workunit API and data/likelihood behavior above are the substantive
  compatibility changes; histogram writer/reader source and checkpoint
  algorithm source are unchanged.
