# S1-04 Settle the log_rn twin mismatch: twin input/model defect or GCC-KNC wrong code?

Sprint 1. Depth: standard. Depends on S1-03 (merged).

## Why
S1-03: the twin runs the card binary's crlibm `log_rn` (44% of host self time on `small`) and gets
`0x43c628b76e3a7b61` for log(1.0), expected +0.0. If the card really computes that, every card result is wrong and
GCC-KNC has a wrong-code bug; if not, the twin or its input is wrong. Gravity was refused because of a PLT `sqrt` call.

## Do
1. Input completeness: list every memory range `log_rn`/`p_accu` read in the twin run (crlibm tables in .rodata,
   constants, stack) and show where each came from in the kernel input. A table missing or mis-loaded is the answer.
2. Card probe (the lead runs it): `probes/libm_probe.c`, built for x86 and card with the same flags and crlibm objects
   as the app, calling `log_rn`, `pow_rn` and the other crlibm/libm functions the app uses on fixed inputs (1.0, 2.0,
   0.5, e, 1e-300, 1e300, subnormal, a few hundred seeded values), and once on the exact captured inputs; prints the
   result bits. `scripts/probe-commands.sh` prints the card_run command. A compare step reports first differences.
3. Twin divergence: run `functional` on `log_rn(2.0)` and other probe inputs too; if the twin can trace, find the first
   instruction whose result disagrees with hand-derived or x86-derived intermediate values. Report a minimal twin repro
   if the fault is the twin's (the lead forwards it to the twin's owner).
4. Gravity: check upstream's real flags for `-fno-math-errno` (CMake files). If upstream uses it, adopt it in both
   builds (then `sqrt` is inline `fsqrt` and the twin can run gravity); rerun the x86 references and the twin gravity
   steps. If upstream does not, leave the flags and say so.
5. Fix the unfilled `{{...}}` placeholders in `docs/twin-check.md` and update it with the new verdicts.

## Engineer report

**Verdict: the observed log_rn mismatch is a twin ISA/model defect, not a missing
or mis-loaded crlibm table. GCC-KNC wrong code is not demonstrated.** Native card
correctness still requires the lead's probe run. Gravity remains unsupported
because of fprintf after the upstream math-errno flag removes the sqrt call.
No valid cycle prediction or bound is available for either function.

Implemented and evidenced:

- `twin/diagnose_log.py`, `twin/log-diagnosis.json`, and `twin/log-memory.md`
  audit every dynamic read with byte-level initialization/store provenance.
  The 16 unchanged-engine log runs make 371 reads over 53 distinct ranges
  (functional/extraction metadata). Every .rodata read matches the linked
  card ELF; no read uses an uninitialized byte, even within an allocated line.
  The inventory identifies inline ELF .rodata initialization, actual stack
  stores and the interpreter's caller sentinel. The raw captured input file
  remains in init.memory and supplies the ABI argument bits. p_accu is fully
  included but none of these faulty-model paths calls it; no coverage of
  unexecuted paths is claimed.
- First divergence for log(1.0): dynamic step 31, instruction `a49727d`, bytes
  `db 44 24 08`, `fildl 0x8(%rsp)`. The preceding 32-bit edi store puts zero
  in the low four bytes of a slot previously containing double 1.0. DB /0
  must load signed m32int zero. The twin's isa.py assigns fildl mem_size=8,
  reading stale high bytes and producing 4607182418800017408 instead.
  Its resulting log return is 0x43c628b76e3a7b61 versus expected +0.0.
  All preceding and following architectural snapshots are retained in
  `twin/log-cases/log-one-intermediates.json`; the engine ISA hash is recorded.
- `twin/fildl-repro.json` is a standalone four-instruction repro, independent
  of crlibm. Its unchanged-engine result/trace under `twin/fildl-repro/`
  shows 0x43cff80000000000 versus zero. `probes/fildl_host.c` independently
  executes the same fildl on x86 and prints zero (`twin/fildl-host.txt`).
  A separately labelled local diagnostic copies the instruction specification
  and changes only fildl's width to four: the captured full log(1.0) then
  matches exactly (`twin/fildl-width-diagnostic.json`). This proves causality
  for the inherited mismatch; it is not a production-engine pass or timing
  result. The shared skill/model files were not modified. Source inspection
  also finds the integer x87 table assigns filds four bytes instead of two.
- `probes/libm_probe.c`, `probes/probe.mk`, and `probes/build.sh` build x86 and
  card probes using the application's common flags and the very same crlibm
  objects for each target. They call log_rn, pow_rn and the other linked math
  families on 1, 2, 0.5, nearest-double e, 1e-300, 1e300, minimum subnormal,
  384 seeded finite positive values, and the captured input bytes. Binary
  functions have fixed second arguments; S1-03 captured only a log input,
  so no captured pow pair is invented. Host output has 20,776 result-bit rows
  in `runs/probe/x86.txt`. Object/probe/input identities are recorded in
  `twin/probe-manifest.json`; linked libm dependencies are inventoried in
  `twin/app-undefined-symbols.txt`. Complex sqrt/pow, sincos, exp2/exp10 and
  hypot are included. The native card probe passes knc_lint.
- `scripts/probe-commands.sh` prints the card_run command and compare step;
  `scripts/probe-launch.sh` supplies the staged runtime path.
  `scripts/compare_probe.py` reports first bit differences and their total,
  rejects missing/malformed/failed output, and accepts the runner's final
  successful JSON receipt. It compares NaN bits exactly too; domain-result
  payload/sign differences alone do not establish a compiler bug.
- Upstream CMakeLists.txt defines and applies `-fno-math-errno` at lines
  288 onward. Adopted it in mk/sources.mk for both targets and in the older
  profiling override. Rebuilt both applications and the card package.
  nbGravity now contains two inline fsqrt instructions and no sqrt call.
  Reran all four gravity steps: unsupported fprintf is now the first callee
  blocker. Updated the closure attempt to include only PLT entries actually
  present; its retained diagnostic rejects fprintf's indirect GOT jump.
  No branches/callees were removed and no stub cycle cost was invented.
- Reran unchanged-engine functional checks on all seven fixed probe inputs,
  eight seeded inputs and the captured input, with independent x86 expected
  bits. All 16 remain functional_mismatch; per-case result.json, summary.md,
  trace, command log and final registers are under `twin/log-cases/`.
  Large generated input kernels and final-memory snapshots remain local and
  gitignored; scripts recreate them. Hotspot validate/functional/simulate/
  bounds were also rerun, retaining the original negative verdicts.
- Rewrote `docs/twin-check.md` and its generator with the new verdicts,
  explicit limits, actual engine fields and filled historical profile values:
  nbGravity 1.75% / 1.22 host sampled seconds, _mcount_private 30.77%,
  __fentry__ 5.87%. These are historical host measurements, not predictions.
