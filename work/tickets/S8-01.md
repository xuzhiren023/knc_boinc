# S8-01 Phase timers for the N-body step, plus a static-schedule integrator build (results unchanged)

Sprint 8. Depth: light. No card access. Deadline: card binaries ready within 45 minutes of start (the lead has a
card window that closes at 02:59Z); do steps 1-3 first, report, then the rest.

## Why
On the large case (20,000 bodies, `workunits/large`), the card takes 30.7 s and the laptop 25.0 s (12 threads), 21.8 s
(vector build) and 136 s (1 thread). The vector force walk gave no card gain, so the force loop is likely not the
dominant term; the serial tree build (`nbMakeTree`, `nbody_tree.c:429`) on one slow card thread is the suspect. We need
measured per-phase times on the card before changing code.

## Do
1. A checked-in patch in `patches/` adding a compile-time option `NBODY_PHASE_TIMERS` (off by default; no effect on
   any computed value when on). With it on, accumulate `omp_get_wtime()` wall time for: `nbMakeTree`,
   `nbMapForceBody` (the force walk), `advancePosVel`, `advanceVelocities`, `get_likelihood` (per-step best
   likelihood), the final histogram/likelihood, and everything from program start to the step loop (setup), plus the
   step count and whole run. Print one line per phase to stderr after the run, prefixed `PHASE` (name, seconds,
   calls), after the `<search_likelihood...>` block so the result contract is untouched.
2. Second compile option `NBODY_STATIC_INTEGRATE`: `schedule(static)` instead of `schedule(dynamic,
   NBODY_FORCE_CHUNK)` for the two integrator loops in `nbody_plain.c` (`advancePosVel`, `advanceVelocities`). Per-body
   independent updates: results cannot change.
3. Builds, same flags as the S7-01 scalar card build (`build/vector/card-off`, chunk 4, `VECTOR_GRAVITY` off), into
   `build/s8/`:
   - `card-timers/milkyway_nbody.mic` (timers on)
   - `card-timers-static/milkyway_nbody.mic` (timers and static integrator)
   - `x86-timers/milkyway_nbody.exe` (timers on, x86 default flags)
   Run the x86 timers build on the large case at 12 and 1 threads (S7-01 command, seed 670828913, 20000 bodies) and
   give the PHASE lines; `scripts/compare.py` against `.work/S7-01/runs/force-chunk/large-chunk196-default-t12`
   must pass bit-identical.
4. Card builds pass `knc_lint`. Print the two card_run commands in the same form as the lead's window script (the
   S7-01 card check: `--benchmark --threads 240`, files `milkyway_nbody.mic`, `params.lua`, `input.hist`, the three
   `dist/card` runtimes, `scripts/card-launch.sh OMP_NUM_THREADS=240 ... --nthreads 240 ... 20000`).
5. Read `nbMakeTree` and its callees and list which parts are serial loops over all bodies (bounding box, insertion,
   centre-of-mass pass, critical radius) and which could run in parallel with bit-identical results (same tree, same
