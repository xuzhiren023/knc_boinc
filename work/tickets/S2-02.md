# S2-02 knc_wrapper: one BOINC task that runs N-body on the card

Sprint 2. Depth: deep. Depends on S2-01 (merged) and Sprint 1. Decisions D5, D6.

## Do
1. `knc_wrapper.exe` (BOINC API, variant from S2-01), reading `knc_wrapper.cfg` from its directory or the slot: card
   host, user, ssh key path, ssh/scp paths (default Windows OpenSSH), remote base dir (default `/tmp/knc-boinc`),
   `OMP_NUM_THREADS` (default 240), poll interval (default 10 s), connect timeout, retry limit.
2. Task flow: `boinc_init_options` with process control handled by the wrapper itself; resolve logical file names;
   make a unique remote dir; stage the card package (binary + runtime .so) and inputs; start the card app detached
   (`nohup`, PID file, stdout/stderr files, `OMP_NUM_THREADS`); poll progress file and PID; report
   `boinc_fraction_done`; on finish copy outputs back to the resolved names, check the exit status, clean the remote
   dir, `boinc_finish`.
3. Control: suspend -> `kill -STOP`, resume -> `kill -CONT` on the card PID; quit -> copy the card checkpoint into the
   slot, kill the card process, exit so the client restarts later; restart with a slot checkpoint uploads it and
   resumes; abort -> `kill -KILL`, clean up. Card unreachable -> bounded retries, then `boinc_temporary_exit` with a
   clear message.
4. The small card-app patch for progress and checkpoint files (D6) if upstream's standalone build lacks them; keep it
   minimal under `patches/`.
5. Make the Cygwin guards in `patches/boinc/` consistent (`__CYGWIN__`; S2-01 review).
6. `--fake-card DIR` test mode: ssh/scp replaced by local commands that run the x86 build in DIR, so every flow above
   is testable on the laptop without the card. Use S2-01's fake client to drive suspend/resume/quit/abort in tests.

## Acceptance
- Tests (fake card + fake client) cover: normal finish with outputs, suspend/resume, quit then restart from checkpoint,
  abort, card unreachable. Each fails before the feature exists.
- `docs/wrapper.md`: config keys, flow, what each BOINC signal does on the card, and what is not proven without the
  real client and card.

## Engineer report

Implemented 2026-11-16 in the S2-02 worktree. No commits, card access, installs,
or writes to the GCC-KNC repository. Used bash and exported TMPDIR, TMP and
TEMP to this worktree's build/tmp before compilation.

Implemented:

- `src/knc_wrapper.cpp`, built by `make -C mk knc-wrapper`, links the actual
  S2-01 BOINC API variant with cooperative process control. Slot config takes
  precedence over config beside the executable. Example configuration is in
  `config/knc_wrapper.cfg.example`; keys/defaults are in `docs/wrapper.md`.
- Logical input/output resolution, unique task directories, binary/runtime
  staging, detached supervisor/PID/exit files, progress polling, output return,
  exit-status checking and remote cleanup. N-body logs resolve as
  `nbody_stdout.txt` and `nbody_stderr.txt` so they do not overwrite BOINC's
  wrapper diagnostics. A slot lease and atomic launch guard avoid duplicate
  remote jobs following an uncertain connection failure.
- STOP/CONT control, acknowledged checkpoint save on quit, checkpoint upload
  and actual upstream restore on restart, KILL/cleanup on abort, finite
  transport deadlines/retries and diagnostic BOINC temporary exits. The app
  is stopped while transferring an acknowledged checkpoint to prevent a
  concurrent periodic checkpoint overwrite. Lost heartbeat follows quit.
- `patches/nbody-wrapper-files.patch`: opt-in safe-step progress and requested
  checkpoints using upstream's checkpoint writer. Testing exposed an upstream
  restart defect: its context stores softening-array pointers without their
  pointed-to arrays. The wrapper-only restore hook rebuilds these arrays from
  identical staged Lua input and recaches body indices, preserving checkpoint
  bodies/step and the existing checkpoint format. It changes no force algorithm.
- Consistent `__CYGWIN__` compatibility guards, including upstream CRT/header
  branches previously depending on the synthetic `__CYGWIN32__` flag. Removed
  that flag and updated the S2-01 build-variant documentation.
- `tests/wrapper.sh` and S2-01 fake-client scenario extensions exercise all five
  required flows through real Win32 BOINC IPC and the real x86 N-body binary.
  Fake transport uses local shell commands/copies with the same supervisor.
  The deterministic unreachable marker exercises the bounded retry path.
  Relative scratch directory creation avoids Cygwin absolute-parent ACL
  traversal failures in this sandbox; the API regression script uses it too.
- `scripts/run_wrapper.sh` is the lead's standalone launcher for a prepared
  slot. The card executable and runtime closure remain in `dist/card/`;
  host wrapper and x86 binary remain under `build/wrapper/` and `build/x86/`.

The five scenarios respectively require resolved histogram/log outputs and
progress; frozen remote progress under STOP and advancement under CONT;
checkpoint retention without a finish marker, upload and upstream restore
on restart; abort status/KILL/cleanup; and bounded retry diagnostics with a
temporary-exit marker and no finish marker. Restart additionally compares
scientific output against uninterrupted execution. The real medium model uses
1024 bodies; test evolution/reverse-orbit times are shortened to 0.1 Gyr to
bound runtime while allowing the control sequences.

S2-01 regression also passed (`build/wrapper-api-regression.txt`): local and
Global/session-fallback IPC layout/progress/checkpoint/suspend/resume/quit/
graphics, plus standalone completion. Updated card build/package passed
`knc_lint` with exit 0 (`build/wrapper-card-final.txt`, `dist/card/knc-lint.txt`).
Pinned commit and patch-state verification via `scripts/fetch.sh`, bash syntax
checks, and `git diff --check` pass. No unrelated tests or card jobs were run.

Not proven: a real Windows BOINC client/service/sandbox, native Windows
OpenSSH/scp path/quoting/timeout behavior against the card, Linux remote
process lifetime under actual disconnects, real k1om checkpoint/restart and
scientific output. The fake card exercises Cygwin processes, not Linux/card
execution. Checkpoints are local to the same build/architecture and require
unchanged task inputs; no cross-architecture portability is claimed. Long
production workunits, bar/LMC/custom-Lua cases and snapshot graphics are not
validated by this shortened model. The lead must perform the real-client/card
integration using their key; `docs/wrapper.md` documents the flow and limits.
