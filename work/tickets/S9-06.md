# S9-06 Parallel, exact partition for the balanced tree (tree bit-identical)

Sprint 9. Depth: deep. No card access. Laptop load light: `make -j2`, identity runs on small/medium/large at 1 and
12 threads only.

## Why
Card, large case, S9-04 `TREE_VARIANT=3` (runs/card/w-knc2/large.txt): nbMakeTree 7.08 s of a 20.95 s run, of which
`tree_partition` 5.93 s runs serially on one card thread; everything else is now small (insertion 0.10, CofM 0.15,
Quad 0.21, threadTree 0.55, expandBox 0.13). Removing most of the partition time takes the large case to ~15-16 s,
below the best x86 build (18.0 s).

## Design (exact)
A body's octant at each level comes from `nbSubIndex` comparisons against the cell midpoint, and a cell's midpoint
comes only from its parent and the octant (`nbInitMidpoint`/`calcOffset`). So each body's octant path can be computed
independently, in parallel, with the same comparisons the serial code makes (descend from the root midpoint, as
deep as the frontier needs, at most the epsilon depth). Then a stable parallel sort (or counting sort per level) by
path groups the bodies exactly as the serial stable partition does, preserving body order within each group; the
frontier and upper cells follow from group counts. No position quantization or Morton bits from coordinates: only
the serial code's own comparisons.
