# S6-01 Prototype: gravity tree walk with one body per vector lane, bit-exact, twin first

Sprint 6 (owner 2026-11-16: "yes" to option A). Depth: deep. No card access. knc-twin at ~/.claude/skills/knc-twin.

## Why
`nbGravity` (`nbody_grav.c`) walks the threaded tree for one body at a time: `q = root; while (q) { far or body?
interact, q = Next(q) : q = More(q) }`. GCC-KNC computes it on x87, one operation at a time (`x87_serial` binds in the
twin). KNC's 512-bit unit holds 8 doubles: 8 bodies can walk the tree in lockstep, each lane following its own `q`,
with masks for lanes that open a cell, interact, or have finished.

## Hard rules
- **Results stay bit-identical**, on x86 and card. Each lane must do exactly the scalar code's operations for its
  body, in the same order: same opening test, same `eps2` choice, same `mw_sqrt`, same quad terms, same summation
  order into `acc0`, same self-interaction and tree-incest handling. No FMA (`-ffp-contract=off`), no reassociation,
  no `-ffast-math`, no approximate reciprocal or rsqrt. Vector add/sub/mul/div/sqrt on KNC are correctly rounded,
  which equals x87 at 53-bit precision except for subnormal/overflow range: say whether that range can occur here.
- No IMCI intrinsics (GCC-KNC has no header yet; ADR-0013 in gcc_knc). Write portable C the vectorizer can map: a
  restructured loop over 8 lanes with if-conversion, or GCC vector extensions (`vector_size(64)`). Prefer the form
  that also compiles for x86 unchanged, so the x86 reference build runs the same code.
- A patch in `patches/`, selected by a build macro (default off = upstream code); the card build turns it on only
  after this ticket's evidence, and that switch is the lead's call.

**Implementation and code-generation limit.** Fixed groups of eight own independent
node pointers, self flags and XYZ accumulators. Guarded pointer reads stage local
SoA arrays, and bit masks preserve inactive accumulator bits. Every real lane
keeps its opening test, eps2 lookup, mw_sqrt, two divisions, monopole sums, quad
phi additions and subsequent quad subtractions in scalar order. The kernel returns
a missing-self mask; its caller invokes the original tree-incest reporting once
per affected body. External-force expressions retain their original order for
each body; the exact all-pairs path is unchanged. No persistent tree copy/refill.

The installed compiler contradicts the flags document's scalar-FP64-division
statement: a vector sqrt/div loop lowers to reciprocal/rsqrt seeds plus fused
refinement even with -ffp-contract=off. An evidence-only object made by removing
`#pragma GCC novector` contains 1 vrsqrt23ps, 4 vrcp23ps, 18 vfmadd and 16 vfnmadd
instructions inside nbGravity8. That object was **never linked or run**. The final
patch keeps that stage scalar instead of relaxing the literal no-FMA/no-seed rule.
Its 368-instruction full kernel contains no FMA/rcp/rsqrt instruction, but still
contains x87 arithmetic. Thus it is a **hybrid prototype**, not the requested
fully vector masked walk. Mask selection is vpandq/vpxorq rather than k-register
predication. Scalar quad arithmetic, pointer packing, stack staging and divergent
walk lengths remain costs.

The full vector computational function has no callees and is extracted intact,
including its epilogue. Its records and adapter constants are identical to a fresh
extraction from the final staged binary. The baseline is the S1-07 compiled
nbGravityChunk calling the unchanged scalar nbGravity eight times. It retains the
same documented cold-error suffix cut; the two functional traces each execute
nine normal returns and never execute the excluded sentinel. All hot instructions
are retained; no timing stubs, overlays, memory defaults or instruction rewrites.
Captured body blocks are deduplicated only after byte comparison, and cell bytes
are initialized inline to avoid thousands of repeated file opens. Original
ctx/state/eps2/body file blocks and captured pointer addresses remain intact.
