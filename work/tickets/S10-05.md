# S10-05 Vectorizable star-setup integrand (block 1) and a measured 1-ULP test

Sprint 10. Depth: deep. No card access. Laptop load light; at most one full 117676 generation per variant (two).
Owner 2026-11-17: fix "block 1" only; leave crlibm (block 2) and the incomplete-gamma series (block 3) alone.

## Why
On the card, core-small star setup is 47.7 s, of which 34.3 s is the parallel quadrature node evaluation of `fun`
(`nbody_mixeddwarf.c`; S10-03 card profile, runs/card/w-knc6/). GCC-KNC cannot vectorize it because:
1. Block 1 (ours): `gauss_quad` calls `fun` through a function pointer, and `get_potential`/`get_density` dispatch on
   the dwarf type with a switch; the node loop is not straight-line code.
2. Block 2: crlibm calls (`log_rn`, `atan_rn`, ...) are correctly rounded scalar calls; GCC-KNC's libknc_vmath is
   within 1 ULP, so substituting it changes intermediate values.
3. Block 3: the incomplete-gamma series has data-dependent iteration counts.
The S9-05 certified vector path replayed 81% of bodies because its worst-case bound is loose; how many bodies the
1-ULP values actually change was never measured.

## Do
1. Block 1, exact (`DF_SPECIAL=1`, own Performance patch, off by default): a specialized node evaluation for the
   models the real workunits use (Plummer light + cored dark, as in the 117676 Lua; others keep the original path):
   no function pointer, no type switch in the node loop, same arithmetic, same order, same crlibm calls. Bodies
   byte-identical (core-small) and likelihood bit-identical. Report `-fopt-info-vec-missed` for the node loop on the
   card compiler: what still blocks vectorization (expected: the crlibm calls and the gamma series).
2. Measured 1-ULP experiment (`DF_VMATH=1`, separate experiment patch, never in the release): on top of 1, use
   GCC-KNC's libknc_vmath (`-mveclibabi=knc -fno-math-errno`) for log/atan/exp where the compiler can vectorize, or
   plain libm calls the compiler maps to them; incomplete gamma stays scalar. No safety net. Generate core-small and
   the full 117676 bodies and count, against the exact reference: bodies that differ (any byte), and the first body
   index where the RNG stream diverges (a flipped accept/reject shifts all later bodies). Also the final core-small
   likelihood and its difference from the exact one. Report the counts plainly; this decides whether a relaxed path
   is worth pursuing.
3. Host timing of 1 and 2 vs the release at 12 threads (one run each), card binaries for both with the release
   options, knc_lint, a core-small window script with predictions.

## Accept
- Exactness proof for 1, vec-missed report, the difference counts for 2, timings, binaries, window script and the
  Effort line in the Engineer report.
