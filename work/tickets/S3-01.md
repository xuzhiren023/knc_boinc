# S3-01 Card snapshots and wrapper relay into BOINC graphics shared memory

Sprint 3. Depth: standard. Depends on Sprint 2. Decision D7.

## Do
1. Card app (minimal patch under `patches/`): every `--snapshot-interval` seconds (default 5) write a subsampled body
   snapshot (at most 20,000 bodies: positions as float32, a type tag dark/light if the app has one, sim time, step,
   fraction done) to a fixed-size binary file, written to a temp name and renamed so readers never see half a file.
   Off by default; cost measured on x86 (must stay under 1% of run time at the default interval).
2. Wrapper: fetch the snapshot with each poll (only when the graphics app could be running is fine, if BOINC exposes
   that; otherwise always, rate-limited), and publish it in BOINC graphics shared memory created with the BOINC API
   (`boinc_graphics_make_shmem` or the Windows equivalent the S2-01 doc identified), with a versioned header
   (magic, version, count, sequence number, status: running/suspended/finished) and the wrapper's own status.
3. Document the shared-memory layout in `docs/graphics-shmem.md` (one header shared by wrapper and graphics app).

## Acceptance
- Fake-card test: the wrapper publishes a snapshot whose contents match the file the x86 app wrote; sequence advances.
- Snapshot format unit test (header, size limits, torn-write safety).
