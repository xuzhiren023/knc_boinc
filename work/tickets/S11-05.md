# S11-05 Repository cleanup and portability for a clone on the owner's workstation

Sprint 11 (last item; after S11-03 lands). Depth: medium. No card access. Host load cap: 4 cores. Do not push; the
lead pushes after review.

## Why
Owner 2026-11-17: after S11, clean up the repo and push it to a remote so the owner can clone it on the workstation
that will host the Xeon Phi. Today 151 tracked files hardcode this laptop's paths (`C:/Users/xuzhi/...`,
`/c/Users/xuzhi/...`: the GCC-KNC toolchain under `gcc_knc/.work/_shared`, card known_hosts and ssh key, the shared
ledger, sibling worktrees), and the repo has no README that takes a new machine from clone to a working build.

## Do
1. One local configuration file (e.g. `config/local.env`, git-ignored, with a committed `config/local.env.example`)
   for every machine-specific path: GCC-KNC toolchain root (cross compiler, binutils, Cygwin bin, runtimes,
   libknc_vmath), gcc_knc checkout (card_run upstream helpers, knc_lint), card host/user/ssh key/known_hosts, shared
   ledger path, BOINC data directory. Scripts, Makefile, tools and the installer read it; no tracked file keeps a
   hardcoded `xuzhi` path except documentation of history (tickets, STATUS, research notes may keep theirs).
2. `README.md`: what knc-boinc is, prerequisites (Windows, Git for Windows, Python 3.8+, GCC-KNC toolchain, MPSS card
   reachable over ssh), clone, `scripts/fetch.sh`, configure `config/local.env`, build (`config/release.env`,
   `packaging/make_package.sh`, `scripts/make-boinc-installer.sh`), test, and install with the double-click
   installer. Link `docs/TRY-IT.md`, `docs/benchmarks.md`, `tools/CARD_RUN.md`.
3. Licence file (owner decision 2026-11-15: project Apache-2.0); keep third-party notices (MilkyWay, BOINC, crlibm) in
   `SOURCES.md`; nothing vendored that is not allowed to be.
4. `.gitignore` covers build/, dist/, runs/, .work/, third_party/, .codex-logs/, local config; `git ls-files` contains
   no binaries, logs, keys, card receipts with secrets, or files over 1 MB except documented images.
5. A `scripts/doctor.sh` (and/or PowerShell) that checks a new machine's setup against `config/local.env` and prints
   what is missing.
6. Tests: the existing offline test suite passes with paths coming from `config/local.env`; a test that no tracked
   script contains a hardcoded user path.

## Accept
