## Engineer report

Implemented in the S1-02 worktree, 2026-11-15/16. No commit, index or branch
changes; no card access or GCC-KNC repository writes. The pinned source was
obtained only through scripts/fetch.sh. Builds used Git Bash and the supplied
Cygwin/GCC-KNC tools, with TMPDIR, TMP and TEMP exported to this worktree's
build/tmp before compilation.

Implemented:

- Shared source/option manifest and handwritten x86/card targets, including the
  exact bundled crlibm source set. NBODY_CRLIBM is now 1 in both builds, matching
  upstream CMakeLists.txt:209. Shared MilkyWay utility/Lua objects retain the
  upstream math selection (milkyway/CMakeLists.txt:108-110). Both use -O2,
  -fopenmp and -ffp-contract=off; card additionally uses -march=knc. No -static.
- Enabled CRLIBM_HAS_FPU_CONTROL explicitly in the checked-in crlibm config.
  Bundled CMake never defines it, so merely enabling crlibm would otherwise
  leave crlibm_init a no-op. K1OM takes the existing AMD64/x87 init path using
  the sysroot fpu_control.h. Cygwin uses crlibm's inline assembly and matching
  control-word constants. No startup patch was needed.
- Static evidence in build/card-crlibm-init.txt shows fnstcw, mov $0x27f and
  fldcw in crlibm_init: 53-bit precision, round to nearest. The main object
  calls crlibm_init in startup before thread configuration; evidence is in
  build/card-main-init.txt. OpenMP workers inherit that environment. This is
  build evidence, not a native observation of every worker's control word.
- dist/card/milkyway_nbody.mic is ELF64, Machine: Intel K1OM, dynamically
  linked with DT_RPATH exactly $ORIGIN:$ORIGIN/../lib. Readelf evidence is in
  dist/card/readelf.txt. knc_lint exits 0; dist/card/knc-lint.txt records PASS.
- scripts/package_card.sh resolves the recursive NEEDED closure and copies
  dereferenced GCC-KNC libstdc++.so.6, libgomp.so.1 and libgcc_s.so.1 from the
  specified gcc-knc-16.2.0/k1om-mpss-linux/lib64 directory. System glibc,
  libm, libdl and libpthread remain card-provided. A unit check compares each
  packaged compiler runtime byte-for-byte with its toolchain source. No card
  GCC 5 runtimes are packaged. Program plus runtime files total 48,268,283
  bytes, below card_run's 64 MiB default staging cap with room for helpers.
- scripts/card-check.sh prints four quoted, runnable card_run commands:
  small 240/60, medium 240, large 240 threads. It never invokes card_run.
  Every input, ELF and runtime is staged with --file. The shell program
  scripts/card-launch.sh exports OMP_NUM_THREADS and OMP_DYNAMIC=FALSE,
  then execs the staged ELF. Runner --threads and application --nthreads
  match. Commands capture combined stdout/stderr and a separate receipt
  under runs/card/. The printer creates that output directory only.
- Upstream --print-histogram supplies the needed histogram without a patch.
  Standalone mode suppresses BOINC's XML wrappers; compare.py now accepts
  this bare n=/lambdaBins/betaBins form as well as tagged histograms and
  legacy run directories. Captures take precedence over histogram.txt,
  ensuring both sides compare the final-state histogram. Saved histogram.txt
  can instead be the best-likelihood timestep. The verdict is solely strict
  likelihood absolute difference < 1e-10 (RunTestUnits.lua:137-139).
  Histogram value/schema differences are diagnostics. Missing, malformed,
  ambiguous and non-finite results are still invalid inputs and fail.
- large uses the permitted 20,000-body fallback. Searches of the project's
  public pages did not locate a current production parameter file proving
  today's count. https://milkyway.cs.rpi.edu/milkyway/old_news.php mentions
  20k in 2015 and 40k run names in 2021; these do not prove the current count.
  large copies the upstream orphan model/histogram, with bounded timeEvolve
  and reverse-orbit tstop both 0.05 Gyr. Other model parameters are retained.
  The resulting histogram has 19,994 in-bin particles out of 20,000 simulated.
  This deliberately bounds host reference time; it is not a full-duration
  production workunit or a long-term scientific convergence test.
- Minimal patches are listed with reasons in patches/README.md: the existing
  popt Cygwin declaration fix; existing CORE-MATH round-even fallback extended
  to K1OM; K1OM guards selecting existing portable fenv paths instead of SSE
  intrinsics; and crlibm's config include path for an out-of-source build.
  Fresh patch application against git-show copies of pinned upstream files
  passed, as did two successive fetch.sh invocations on patched sources.
  The two CORE-MATH patches no longer overlap, so reverse checks are idempotent.
