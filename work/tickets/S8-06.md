# S8-06 Pilot-study ledger: twin and model effort vs card effort per ticket, with scoring

Sprint 8. Depth: light. No card access, no network. Read-only on everything outside this worktree.

## Why
The owner runs knc-boinc as a pilot study of how the knc-twin skill (simulated KNC), the knc-optimize skill (model
first) and GCC-KNC work together, compared with runs on the physical card. We need, per ticket and per sprint, how
much effort went to each and how well the simulation/model predicted what the card then showed. The numbers must be
regenerated by a script, not typed by hand.

## Do
1. `tools/pilot_metrics.py` (standard library only) that scans this repository and writes
   `docs/pilot-study/metrics.json` and `docs/pilot-study/README.md` (tables). Sources (main repo path
   `C:/Users/xuzhi/Documents/knc-boinc`, read-only):
   - Tickets `work/tickets/S*.md`: sprint, title, depth; whether the ticket used knc-twin, a model table
     (knc-optimize / model-first), GCC-KNC variant builds, card runs (from the text and the Engineer report).
   - Engineer effort: `.codex-logs/<ID>-<n>.jsonl` (session count, wall time first-to-last event, token usage if
     the events carry it).
   - Twin effort: every knc-twin `result.json` under `twin/` and `.work/*/` (command, status, result_class,
     simulated instructions/cycles if present, host seconds if present); count by ticket and status
     (ok / unsupported / missing_parameter / other).
   - Card effort: card_run receipts (`*.json` with `card_minutes`) under `.work/*/runs/card/`, `runs/`, and the
     shared ledger `C:/Users/xuzhi/Documents/card-coordination/jobs.jsonl` rows whose purpose or path names
     knc-boinc or MilkyWay (job count, card minutes, window). Map each receipt to a ticket by its path.
   - Predictions vs measurements: rows the lead lists in `docs/pilot-study/predictions.json` (create it with the
     entries below; the script reads it).
2. Tables in the README: per ticket (sprint, ticket, engineer sessions and hours, twin runs ok/unsupported, twin
   host seconds, model table yes/no, card jobs and card minutes, outcome); per sprint totals; and a scoring table.
3. Scoring (per prediction row): predicted value, measured card value, ratio, direction right (did the prediction
   pick the same winner / sign of change as the card), and a twin-usefulness class: `decided` (twin or model
   ranked variants and the card agreed), `missed` (card disagreed), `unsupported` (twin could not run),
   `not-attempted`. Totals: card minutes spent, card runs avoided by twin ranking (variants ranked off-card and
   never sent), hit rate of direction-right.

   - S8 model (docs/research/s8-model.md): parallel tree predicted 1-2 s on the card; measured 70.4 s (S8-02).
   - S8 model: serial share of the large case ~27 s (thread-sweep fit); measured tree 13.2 s + other serial
     ~1.5 s; force 13.0 s did not scale as P/t predicted.
   - S8-04: twin `unsupported` on both tree insertion and mixed-dwarf `fun` (cold calls, indirect call, jump table).
   - S1-05/S1-06/S1-07 twin checks (functional ok on gravity; 1-ULP x87 double rounding found in the twin, fixed
     as knc-twin T1-06).
5. A test `tests/test_pilot_metrics.py` on a tiny fixture tree (one ticket, one log, one receipt, one twin result)
   that checks the tables' numbers.
