# S8-02 Parallel tree build with the identical tree (results bit-identical)

Sprint 8. Depth: deep. No card access. Deadline: a card binary within 75 minutes of start (card window closes 02:59Z).
S8-01 (phase timers, static integrator) runs in parallel in `.work/S8-01`; if its patches exist when you build the
card binaries, include them (same patch files), otherwise build without them and say so. Do not edit S8-01's files.

## Why
Window 12 card sweep on the large case (20,000 bodies): 60 threads 41.6 s, 120 threads 36.1 s, 240 threads 30.9 s;
the fit gives ~27 s that does not shrink with threads. The laptop takes 25.0 s at 12 threads. `nbMakeTree`
(`nbody_tree.c:429`) runs on one card thread every step: `expandBox`, `nbLoadBody` per body, `hackCofM`, `threadTree`,
`hackQuad`. S8-01's PHASE lines give the measured split; this ticket parallelizes the tree build without changing a
single bit of any result.

## Facts that make an identical parallel build possible
- With one body per leaf, the octree shape for a given body set and root box does not depend on insertion order;
  a cell's midpoint comes only from its parent and the octant (`nbInitMidpoint`). Children are kept by octant
  index (`Subp(q)[i]`), so `threadTree`, `hackCofM` and `hackQuad` visit them in the same order whatever the build
  order or the cell addresses.
- `expandBox` is a max over |differences|: exact in any order.
- `hackCofM` and `hackQuad` compute each cell from its children in octant order: subtrees are independent.

## Do
1. A checked-in patch in `patches/` under a compile-time option `NBODY_PARALLEL_TREE` (off by default; card build on):
   - `expandBox`: OpenMP max reduction.
   - Insertion: bucket the bodies by their octant path to a fixed depth D (2 or 3; justify), keeping body order
     inside each bucket. Create the top cells serially exactly where the serial code would (a cell where at least two
     bodies share the octant; a single body sits directly in its parent's slot), then let each thread insert the
     bodies of whole buckets into their own subtree with the existing `nbLoadBody` descent starting at that cell.
     Per-thread cell allocation (no shared free-list race); merge `cellUsed` (sum), `maxDepth` (max) and
     `structureError` (or) afterwards. Keep the `qsize <= REAL_EPSILON` and test-particle (`Mass == 0`) behaviour.
   - `hackCofM` and `hackQuad`: run the subtrees below depth D in parallel (OpenMP tasks or a parallel for over the
     depth-D cells), then finish the top levels serially in the same octant order.
   - `threadTree` stays serial unless the PHASE lines show it matters.
2. Proof of identity on x86 (the test that matters): a debug check (compile option) that builds the tree both ways
   for the same bodies every step and compares shape, every cell's `Pos`, `Mass`, `Rcrit2`, `Quad` bit for bit, and
   the `Next`/`More` walk order; run it on small, medium and large at 1 and 12 threads with no mismatch. Then
   `scripts/compare.py` bit-identical against the references (`.work/S7-01/runs/force-chunk/*-chunk196-default-t12`)
   for small, medium, large at 1, 4, 12 threads.
3. Card build `build/s8/card-ptree/milkyway_nbody.mic`: S7-01 scalar card flags (chunk 4, `VECTOR_GRAVITY` off),
   phase timers on, static integrator on, parallel tree on; passes `knc_lint`. A second one with `VECTOR_GRAVITY=1`
   as `build/s8/card-ptree-vec/`. Print both card_run commands in the window-script form.
4. x86 PHASE lines for the large case at 12 threads, before and after.
